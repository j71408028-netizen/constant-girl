# 界面术语表

> 本表收集程序里**给人看的词**——界面标签、按钮、提示、报错、说明文字、
> 送进 AI 的提示词里出现的领域词。目标不是术语一致性，而是让玩家/作者第一眼就懂、
> 不会把 A 当成 B，并且整套文案读起来是同一个世界的人在说话。
>
> 按身份查表：
> - **玩家**：读 [§1 一览表](#1-一览表) 就够；
> - **资源创作者**（副本方案 / 行为包 / 世界包作者）：写文案、提示词前查 §1，
>   文案可被覆盖的位置见 [§2](#2-代码层面的说明)；
> - **代码开发者**：标识符对照与命名约定见 §2；改了玩家可见词回写 §1，
>   改了标识符去 `docs/Dungeon/domain_terms.md`。
>
> 相关：[角色演化全景](designs/character_evolution.md)（潜质/深度/敏感值/重力怎么算）、
> [副本数据模型](designs/dungeon/script.md)（章节与触发器）、
> [行为包开发指南](designs/behaviors/dev-guide.md)（文案可被覆盖的位置）。

## 1. 一览表

### 1.0 三条硬规则

1. **一个词只指一件事。** 同一个中文词出现在两处，必须能被同一句话解释；
   做不到就拆词，不改定义。
2. **词要能进句子。** 玩家会看到「她的观测等级是 Medium」这样的句子，
   不会看到「e9 号」这样的句子。所有术语都要经得起「填进一句人话」的检验。
3. **同一量纲的词要用同一种构词。** 「…等级」对「…等级」，「…值」对「…值」，
   「…度」对「…度」。跨量纲的对称是错的——敏感值与重力是不同量纲的两个系数，
   各自命名优先，不受此条约束。

### 1.1 副本（`副本` / `副本方案` / `剧本`）

| 词 | 用在哪 | 一句话 |
|---|---|---|
| **副本** | 功能名：会话窗口标题、设置分组、报错里指整体 | 一套可以「进去玩」的互动叙事功能 |
| **剧本编辑** | 主窗口导航栏的编辑器入口（页面键 `scenario`）；他处指名该页面时同用 | 编辑副本方案的功能页 |
| **副本方案** | 编辑器内部、配置界面标题、章节/触发器相关正文、设计文档 | 作者编写的**定义**：章节、触发器、提示词、演化属性、结局与素材 |
| **剧本** | 外部入口与窄容器——见下方判定条件 | 「副本方案」的口语简写 |

同时满足下列全部，用「剧本」；否则用「副本方案」。

1. 位置在**剧本编辑器之外**（ME/挂件模式的调查卡、简报详情行、外部入口列表、挑战页）；
2. 该控件是**单个短标签或单行摘要**（标签字符数 ≤ 4，或摘要只作一行的前缀词）；
3. 上下文已经明确是「一次游玩的对象」，不需要与其他「方案/设定/配置」区分。

配套词：**一局**（一次具体游玩）替代「局」单用；**回放**（已有记录的重看）；
**章节 / 触发器 / 结局**在编辑器与玩家侧同名，不改。

**副本内部的层级词**：

| 词 | 定义 | 易混点 |
|---|---|---|
| **章节** | 副本的一个叙事段落，带地点、提示词、演化配置 | 不是「段落」，也不是「场景」 |
| **段落** | 章节内生成的**一段正文**，每段结算一次步进 | 与「章节」差一层，别混 |
| **触发器** | 满足条件时执行一个动作（跳章、改效果、开小游戏、给结局） | 不是「事件」——「事件」在取材与报告里另有含义 |
| **结局** | 一局的终止状态，可带图标与文本 | 与「结束」不同：结束是流程，结局是内容 |
| **指令** | 段落首行的方括号标注，如 `[互动 +1]` | 玩家不写指令，AI 写；作者界面也不叫「标签」 |
| **方向** | 指令里的 `+1/-1/0`，或 `介入度+1` 这类只改一路的写法 | 方向不是「变化量」，它乘深度之后才是 |

> 段落类型（环境 / 分支 / 对话 / 互动 / 行动）在编辑器里直接显示中文名，
> 不显示 `background` 这类英文键。

### 1.2 观测等级（`观测等级`）

**定义**：按身高把角色归入 5 档，回答「这个世界以什么尺度面对她」。

| 档位 | 身高区间 | 换一种说法 |
|---|---|---|
| Small | 7.5~50m | 可以被一栋楼困住 |
| Medium | 50~300m | 比地标高，但仍在城市天际线内 |
| Large | 300~1800m | 城市是她的落脚点 |
| Huge | 1800~10000m | 城市是她的地毯 |
| Colossal | 10~150km | 城市是她的皮肤纹理 |

- **档位名用拉丁名，与耦合等级一致**，不译。区间串（`7.5~50m`）只是附注，不进档位名。
- **不是**地标的「尺寸」（12 档 `0~3米` … `300千米以上`，见 §1.6），**不是**
  ME 的尺度档（`No limits / Medium / Mega / Giga`），**不是**「身材预设」。
- 「体型」退回它本来的意思：**身体形态**（身材、外观预设、巨大化设定）。
  除上述三套分档外，任何以「体型」代指身高档的文案都应改为「观测等级」或「身高」。

### 1.3 耦合等级（`耦合等级`）

**定义**：玩家以**什么身份**进入副本，3 档：

| 档位 | 玩家是谁 |
|---|---|
| **Velum** | 纯读者：只读剧情，不能改变走向 |
| **Solea** | 任务执行者：可接受任务、以团体身份接触 |
| **Bulla** | 个体互动者：与她一对一直接互动 |

- 与观测等级是**两个正交轴**：耦合等级说**你是谁**，观测等级说**她多大**。
  别在文案里把两者合成「难度」或「等级」一个词。
- 档位名沿用拉丁名，UI 不要加中文副标题（副标题用在下拉展开的说明区域，
  不进档位名本身）。

**「级」的用法**：**只有数字才叫「级」**——介入度分 1~4 级、破坏性分 1~4 级，
写「介入度 3 级」。带固定档位名的（观测等级、耦合等级）叫「等级」。
两套词不要互换，「耦合等级 3 级」是不存在的说法。

### 1.4 性格：分层与各层术语

角色档案里有三组容易混的东西：**日常性格**（普通少女也成立）、**巨大化潜质**
（巨大化叙事特有）和**角色状态**（当前可观察量）。它们不是同一层，也不是同一把尺子；
真实关系是「日常性格调制潜质的展开，潜质展开成状态」。

| 层 | 术语 | 回答的问题 |
|---|---|---|
| **日常性格** | 敏感值 / 重力 / 策略值 / 个性强度 | 她平时是否易受他人或环境影响、是否执着于自己的兴趣 |
| **巨大化潜质** | 介入潜质 / 破坏潜质 | 普通少女巨大化后会暴露多少底色 |
| **潜质展开（深度）** | 介入深度 / 破坏深度 | 每单位步进，她向那一侧陷得多深 |
| **角色状态** | 介入度 / 破坏性 | 她此刻表现出多少 |
| **输入** | 步进 | 这段文本把故事推进了多少 |

**巨大化潜质与深度**：

| 词 | 定义 |
|---|---|
| **介入潜质** | 普通少女巨大化后可能暴露的介入底色；不是意向，也不是当前状态 |
| **破坏潜质** | 同上，破坏一侧 |
| **介入深度 / 破坏深度** | 潜质展开的速度：每单位步进深入多少；正数越陷越深，负数逐渐抽离。性格档案里存初始值，状态里存当前值 |

- **潜质/深度不替她做选择。** 它们只描述巨大化后她暴露出来的底色和展开速度；
  行动策略仍归 AI。这样「潜质」与「策略」也不会互相占名。
- **0 的含义**：潜质为 0 表示没有固定潜质，巨大化后随机演化；对应的深度滑块禁用。
- 「深度」在公式里是速率，不是静态深度：
  `介入度 += 介入深度 × 步进`。若面板上没有这行解释，应改叫
  「介入深化速度 / 破坏深化速度」；有解释时「深度」的叙事味更好，推荐保留。
- 潜质与状态**不是别名**，文案分两套：**潜质/深度描述**写「她潜藏着……」
  「如果巨大化，她大概会……」，允许主观倾向；**状态描述**写「此刻她……」，
  尽量客观——破坏性的状态只写后果（「她所过之处……」），不写「享受/乐意」。

**日常性格**：

| 词 | 定义 | 改哪个量 |
|---|---|---|
| **敏感值** | 她对**人类的情绪与请求**有多敏感 | 介入度 / 介入深度 |
| **重力** | 她受**地标风貌与破坏诱惑**牵引有多强 | 破坏性 / 破坏深度 |
| **个性强度** | 她的性格有多「定型」：恢复潜质的速度、对兴趣的执着 | 深度与行动点 |
| **策略值** | `敏感值 ×(1−归一行动点数) + 重力 × 归一个性强度`；用于不直接归属介入度/破坏性的属性 | 其余属性 |

- 这一层是**日常也成立**的普通性格。它不依赖巨大化，但会调制潜质的展开。
- **策略值不是第四个独立旋钮**：它是敏感值与重力的合成，面板上只作为描述行，不设滑块。
- 在公式里，敏感值/重力/策略值统称 **性格系数**；个性强度是这一层的**稳定性**参数，
  不并入性格系数。
- 一句话记住——**敏感值管「别人怎么对她」，重力管「地方怎么诱她」；两个都落在状态上。**

### 1.5 「敏感」的归属

「敏感效果」已改称「演化修正」（见 §3 历史）。此后高频界面里
「敏感」只指**日常性格「敏感值」**，不再有第二义：

| 含义 | 出现在哪 | 是什么 |
|---|---|---|
| **敏感值** | 角色创建/参数面板 | 日常性格，§1.4，作用于介入度 |
| **演化修正** | 章节「持续演化修正」、触发器「演化修正」 | 对属性每步增量的限时加减项 |
| **大小写不敏感** | 搜索、匹配的技术提示 | 技术语，非领域词，不受本表约束 |

「演化」指角色每一段文本走一步、状态/属性随这一步变化，全系统统一叫法见
[角色演化全景](designs/character_evolution.md)；修正量正挂在这一步上。

### 1.6 三套「尺寸 / 尺度」分档

程序里有三套分档，服务于不同场景，**不要互相简化成一套**：

| 名称 | 档数 | 用途 | 在哪看到 |
|---|---|---|---|
| **观测等级** | 5（Small…Colossal） | 角色身高归类；决定描述与素材的选取 | 角色参数面板、目标筛选、AI 提示词 |
| **地标尺寸** | 12（`0~3米` … `300千米以上`） | 地标与参照物的物理大小，用于距离与换算 | 地标编辑器 |
| **ME 尺度档** | 4（`No limits / Medium / Mega / Giga`） | 挂件模式的生成尺度偏好 | ME 参数面板 |

- **地标的「尺寸」不叫「等级」**：它是连续区间，不是档位名。
- **ME 尺度档**是筛选器口径，不进正文，也不与观测等级对照展示——
  两者都能细分到 Medium，但含义不同（一个是身高档，一个是生成偏好）。
- 三套都要避免在文案中出现裸「体型」二字。

### 1.7 资源与行动

**资源层（世界包内部）**：

| 词 | 定义 | 备注 |
|---|---|---|
| **世界包** | 一整套可启用/禁用的资源集合：地标、描述、取材表、副本方案、挑战包、行为包 | 启用中的世界包会**接管**其打包的资源；同一时刻只有一个生效 |
| **地标风格** | 一组地标及其地址注册，决定「她身边有什么」 | 打包类型名，与「描述风格」并列 |
| **描述风格** | 一组描写模板（quip），决定「事情怎么被说」 | 打包类型名；`quips` 的中文对译 |
| **取材表** | 一组四张表（人名、地名、新闻等），同时生效、切换即时 | 不是「素材库」，也不是「素材包」 |
| **行为包** | 不改主程序、替换指定函数行为的包 | 覆盖了点就说「行为已更改」，不说「已接管」 |
| **挑战包** | 固定条件的副本挑战，独立于世界包单列 | `.chal` 文件 |
| **接管** | 资源包替换了某项实现 | **玩家界面不说「接管」**：navbar 显示「行为已更改 N 项」。只有诊断日志与文档可以用 |

> 「取材表」不是「素材」：素材是图片音频，「取材」是随机取色的文字表。这两个词
> 在界面里必须分开，否则「换素材」会被理解成换图。

**行动与消耗**：

| 词 | 定义 | 备注 |
|---|---|---|
| **行动点数** | 生成、进入副本、切换地址消耗的资源，0~100 | 首次出现处给全称，之后可写 **AP**；不要一开始就写 AP |
| **进入准入** | 副本入口的三项门槛：入口地址、最远距离、身高区间 | 字段名不改；注释与文档不要写「体型准入」 |
| **初始提示 / 系统提示** | 发给 AI 的开场与常驻设定 | 两者不是同一个字段，别混称「提示词」 |
| **主角称呼** | 副本里玩家角色的称谓 | 仅 Solea/Bulla 生效，Velum 置灰 |

### 1.8 不该出现在界面上的词

以下词只属于实现层与设计文档，**任何界面文案、报错、AI 提示词都不许出现**：

| 内部词 | 人话怎么说 |
|---|---|
| **二阶量** | 介入深度 / 破坏深度；也不得用「性格二阶量」指性格系数 |
| **归一行动点数 / 归一个性强度** | 不解释；只出现在公式说明里 |
| **策略值** | 除介入度、破坏性之外的属性用的性格系数；作者界面按需展开说明 |
| **出身烙印** | 「按世界规则派生的角色初始模型参数」。玩家侧不出现，文档里出现时首次加注 |
| **接管** | 行为已更改（见 §1.7） |
| **坐标** | 介入度 / 破坏性本身。**玩家文案说「介入度」就够**，不解释它是坐标 |
| **属性条 / 自定义属性** | 属性条可以出现（它是 UI 组件名）；「自定义属性」仅在方案编辑器里用 |

> 判定口径：一个词如果必须配一句公式才能解释，它就不该进玩家界面。

## 2. 代码层面的说明

### 2.1 两张表的分工

- **本表管文案**，代码标识符归副本领域术语索引 `docs/Dungeon/domain_terms.md`。
  冲突时以各自的表为准，不要跨表改字。
- 技术文档保留 `sensitivity` 等标识符不改名；玩家可见词与本表对齐即可。

### 2.2 术语 ↔ 标识符对照

| 术语 | 标识符 | 备注 |
|---|---|---|
| 步进 | `step` / `DungeonTextType.step_value` | 词与码互译不受历史改名影响 |
| 介入潜质 / 破坏潜质 | `Personality.init_intrusion` / `init_destruction` | 不改 |
| 介入深度 / 破坏深度 | `Personality.depth_intrusion` / `depth_destruction`（状态侧快照属性 `current_depth_*`） | 原名 `step_intrusion` / `step_destruction`，随术语一起改 |
| 介入度 / 破坏性 | `CharacterSnapshot.intrusion` / `destruction` | |
| 敏感值 | `Personality.sensitivity` | 标识符不改名 |
| 重力 | `Personality.gravity` | |
| 策略值 | `Personality.strategy_value`（派生） | |
| 个性强度 | `Personality.skip_base_prob` | |
| 观测等级 | `core/logic/sizing.py`：`SIZE_CATEGORIES` / `SIZE_LEVEL_NAMES` / `SIZE_DISPLAY` / `get_size_category` | |
| 档位名 + 区间附注 | `size_level_text(category)` → `Small（7.5~50m）` | 界面显示观测等级的唯一出口，下拉与单选都走它 |

### 2.3 行为钩子名

演化相关的行为钩子随术语改名（2026-11 破坏性更改期落地）：
`evolve_step_rates / decay_step_rates / nudge_step_rates` →
`evolve_depths / decay_depths / nudge_depths`。

### 2.4 改动同步点

- 改了**玩家可见词** → 本表 §1 是唯一真相；
- 改了**代码标识符** → 去 `docs/Dungeon/domain_terms.md`；
- 档位名、区间、档位顺序改动了 → 同步 `size_level_text` 与本表 §1.2 的区间表。

## 3. 历史

### 3.1 旧称对照

| 旧称 | 新称 |
|---|---|
| 敏感效果 | 演化修正 |
| 持续敏感效果（章节） | 持续演化修正 |
| 敏感效果倍率 | 演化修正量 |
| 初始介入度 / 初始破坏性 | 介入潜质 / 破坏潜质 |
| 介入度步长 / 破坏性步长 | 介入深度 / 破坏深度 |
| 性格二阶量 | 该属性的性格系数 |
| 二阶量 | 停用；直接说深度 |
| 检查体型准入（注释） | 身高准入 |

### 3.2 决策记录

- **「体型分类」为什么叫「尺寸等级」**：与 **耦合等级** 对称。两者都是「给一个连续量分档、并给档位
  起名」的同一类概念。而「分类」在程序里已用于地标类型、段落类型，容易串味。
- **「步进」保留原名**：曾短暂改为「推进量」（2026-11），评估后回退——三个字放进
  「每段结算一次步进」这类句子里不自然。标识符本就是 `step`，词与码互译不受影响。
- **「破坏性」保留**：若将来要追求三段式完全对称，可改「破坏度」（介入度/破坏度），
  但这是另一笔账；当前以「破坏性」作为档案状态名。
- **潜质 / 深度 / 度 三层构词不对齐是有意的**：强行对齐（如「潜质值 / 深度值 / 度值」）
  会把层级重新混掉。
- **导航栏与页面名用「剧本编辑」，编辑器内部文案仍用「副本方案」**（2026-11 定）。
- **潜质不叫「意向/倾向」**：潜质是能力与底色，不是意愿。将来真加
  「介入意向 / 破坏意向」，两者可以并存——潜质说她会暴露什么，意向说她想要什么。
- **「重力」保留不改名；也不采用「敏感度」作同义词**：文案里一律写「敏感值」。
  「重力」只在角色参数面板与演化公式说明两处出现，语境里不会读成物理引力；
  改成「…值」会丢掉「地标像有质量一样把她拉过去」的意象。
