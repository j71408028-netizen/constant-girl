# 报告生成：地标 × 描述的选取与配对

> **这一篇回答什么问题**：你点下「生成报告」之后，报告里的地标对比和事件描述是怎么凑到一起的——哪些地标能进、每条地标配哪段话、谁排在前面。同一套规则也决定着你写的地标 / 描述风格什么时候会被用上。
> - **普通玩家**：§1 讲一份报告由什么凑成，§2～§3 解释「这段描述为什么配的是这个地标」「合身的地标为什么没排第一」，§4 是报告里那些额外信息。
> - **地标 / 描述风格作者**：§2 的车道决定你的内容能不能用上，§3 的顺序决定它排在哪，§6 有两个现成写法。
>
> 相关页面：地址怎么写、怎么注册 [address_system.md](address_system.md) · 她的空间档案与离线结算 [character/time.md](character/time.md) · 演化公式 [character/evolution.md](character/evolution.md)。

> **名词对照**：程序里把「谁配谁」的裁决叫**仲裁**，把「一段描述能作用在哪些地标上」叫**车道**。正文沿用这两个词，界面上都不会出现。

## 1. 一份报告由四步凑出来

报告不是随机抽的，而是同一条流水线上四道工序的产物。你读报告时的每种感受，都能对到其中一步：

| 工序 | 管什么 | 你看到的结果 |
|---|---|---|
| 尺寸匹配 | 按部位 × 地标的倍率挑候选，只管「合不合身」 | 对比对象总是和她差不多大的东西 |
| 空间裁决 | 排除到不了、维度对不上、私有名冲突、已损毁的地标 | 太远的东西不会出现；这一带的地标才会被讲到 |
| 描述配对 | 给每个入选地标挑一段合适的描述 | 有的地标配着细节丰富的故事，有的只有一句占位话 |
| 演化推进 | 介入度 / 破坏性、深度、伤亡、地标耐久、位置写回 | 报告之后她确实动了、也确实留下了痕迹 |

地标耐久只对独特地标结算，且**声明为不可破坏（`destructible=no`）的地标不参与**：它们永远显示完好，也不会因为「已损毁」从候选、落脚点里消失。判据是叙事权限而不是物理可能性——地球撞得碎，但故事可能不许可。

**合不合身始终是主线**。后面三步都在「已经合身」的候选里做微调：空间只负责否决，描述只负责修饰，顺序只改变呈现——没有哪一步能把一个不合身的地标推上来。

尺寸匹配之前还有一道数据校验：**尺寸不是「正数且有限」的地标直接不参与**（`0` 会让比值除零，负数方向反了，NaN / inf 能绕过倍率区间判断）。CSV、挑战包导入、副本载荷与编辑器共用同一条判据 `core/models.py::is_valid_landmark_size`，坏行在入口就被丢弃并打印行号；就算数据从别的缝隙钻进来，挑选时也会跳过它——一行坏数据不该让整份报告失败。

## 2. 描述怎么配到地标上：车道

每个入选地标（报告里的一个槽位）× 每个你选的描述风格，按风格的注册地址判一条车道。车道决定这段风格「能不能用在这儿」以及「有多优先」：

| 车道 | 判定 | 权重 |
|---|---|---|
| 同址 | 注册地址与地标地址**完全相同** | 1.0 |
| 覆盖 | 注册地址**更粗**、把地标地址包在里面 | 0.8 |
| 自由 | 风格没注册地址，或地标本身没地址 | 0.5 |
| （不参与） | 不覆盖、维度不同、私有名冲突 | 该地标不用这段风格 |

四条对作者有用的推论：

- **注册得粗 = 用得上但排在后面**：注册到维度级就能给该世界所有地标写描述，可同址注册的风格在同一个地标前永远更优先；
- **没地址的地标对所有风格开放**（自由车道）：那类「常见地标」不注册地址也能拿到描述；
- **描述池只消耗、不裁剪**：选一条少一条，但前一个地标没用完的窄覆盖风格不会因此被删掉，后面同址的地标照样能用；
- **池子耗尽的槽位降级成纯对比**，正文写「尺寸通过远程测量取得，尚未收集到事件记录。」——一句占位话，不会让整份报告中断。

## 3. 谁排在前面

默认的「按匹配」模式下，报告按综合分排序：**尺寸匹配为主**，再乘三层调制——

1. **覆盖收益**：车道里还有描述可用的地标，略微优先；
2. **她的空间档案**：常去的区域优先、长期不去会衰减回中性；手工标注的活动区域命中；旅行 / 地理测量这类标签偏爱有地址的内容，四处走走 / 能躺着不站着偏爱活动范围。姿态类标签不在这里，它们早在尺寸匹配时就生效了；
3. **路径连贯**：离她当前位置近的，略微优先。

**近匹配提拔**是这套排序里唯一会「换人」的机制：如果最优匹配的地标一句描述都没有（车道全空，或池子刚好被前面的槽位用光），而尺寸差在容差带内（约 1.4 倍以内）的次优地标自带覆盖，次优就被换到前面。每份报告的提拔次数还有上限（对比数的一半）——**覆盖只破平局与近局，不推翻尺寸匹配的主导地位**。

两条边界：

- 你在设置里选了**按尺寸排序**（升序 / 降序），报告就保持你的呈现选择，这两条只保留「活动区域前移」与「近匹配提拔」；
- **旧档案**（没有到访历史、没有空间标签）所有档案权重中性，等于只看尺寸与覆盖。

**自然叙述顺序**（设置里的同名选项）是另一条路：报告按空间行走的先后呈现——从她当前位置出发，每一步挑跳转距离最近、且真的到得了（同维度、私有名约束满足）的槽位，落点跟着前移，串成一条地址跳转链；跨维度、没地址的槽位稳定排在末尾按尺寸兜底。没有起点时退化成尺寸序。它仍然只是**建议序**，可达与否、落点怎么演化依旧由空间裁决那一关说了算，近匹配提拔也照常作用在它上面。

<details>
<summary>环境一致性与环境偏好（觉得描述和场景不搭、或想查她为什么偏爱某类地点时展开）</summary>

**环境一致性**：她的空间档案里有一条环境轴，把在线报告沉淀下来的环境证据按地址聚合，为每个带地址的槽位估一个环境值（一点证据都没有时为 `None`）。挑描述时对每条候选文本采样一次环境因子，与槽位估计偏差越小加分越高——所以她更愿意讲和所在环境相称的故事。三条铁律：**零证据零权重**（没沉淀就不制造伪偏差）；**软权重不做硬闸**（全池都矛盾时，矛盾文本照常被选，池耗尽降级也不受影响）；**环境只影响文本选取**，不进地标可达与配对的几何口径。

**环境偏好**：另一条轴从「步进 > 0」的沉淀行里学她偏好什么环境（值域等宽分箱直方图 + EWMA 淡出），出身烙印带来的环境份额先验（创建时按默认表合并，旅行 / 地理测量偏爱人烟稀少）作为伪计数初值，并受成熟度阻尼压低权重——步进的正负是相关性，不是因果。它只在仲裁的联合分里生效：带地址的槽位按环境估计查偏好分布，乘一个调制因子，她常讲的环境里的地标略微优先。中性档案（没证据、没先验标签）恒为 1.0。

这两条都经**创建期烙印**进入档案，不是运行时读的常量——烙印终身携带，换世界包也不改。

</details>

## 4. 报告里还带着哪些信息

每份报告还会生成两份旁证，供后续界面与排查使用，**目前只是数据、没有上界面**：

- `coverage`：星槽数、浪费掉的风格、实际触发的风格；
- `promotions`：提拔记录，谁让位给了谁。

如果你在排查「我的风格明明写了却没出现」，看这两个字段比读整份报告快。

## 5. 内部实现

四道工序各有一个落点，边界要分清：尺寸匹配在 `core/logic/quips.py::get_comparisons`；空间裁决、车道窗口与顺序调解在 `services/exploration/arbiter.py`；描述的实际挑选与预算在 `services/exploration/quips.py::select_quip_with_budget`；坐标、深度、伤亡与耐久的推进在 `services/exploration/report.py::ReportEngine`。

- **描述选取不对行为包开放**：资格过滤（车道窗口）在 `_quip_candidates` 里完成，属于裁定级；`select_quip_with_budget` 只负责在窗口内按预算选句，环境一致性仍是软权重。
- **仲裁的决策面开放为 `report` 组**：车道窗口、联合分、近匹配提拔是模块策略钩子；容差、提拔上限、联合分权重、可达范围等模型参数是 `report.model.*` 常量钩子。硬闸、物理走查与 stuck 判定不开放（逐项见 [hooks-report.md](behaviors/hooks-report.md)）。

## 6. 拓展用法

界面上没写、但程序实际支持的两种写法，都只在你的数据目录里动：

- **通用旁白可以故意不注册地址**：风格注册得越粗越通用、权重越低。如果你写的是不带地点色彩的旁白（谁都能用的那种），不注册地址反而覆盖面最广——它会走自由车道，在同址与覆盖风格都用尽之后接管剩下的槽位。
- **地标不写地址也能进报告**：地址列留空的地标不参与私有名筛选，但照样能被尺寸匹配选中，并靠自由车道拿到描述。适合「四处都有、不值得申领地址」的常见参照物。

## 7. 参数表

`report.model.*` 的逐项默认值与说明以 [hooks-report.md](behaviors/hooks-report.md) 的常量表为准，默认值登记在 `services/exploration/arbiter.py` 顶部与 `quips.py` 的注册处。这些是**建议值**：行为锁只锁语义不锁数值，调整后跑一遍 §8 的测试确认语义没破即可。

空间 / 环境侧没有运行时钩子：调制经创建期烙印（`CreationService.derive_model_tuning` 返回 `ModelTuning`）进入角色档案；`_ENV_PRIOR_K`、`_ENV_PREFERENCE_SMOOTHING` 这类学习层参数不开放（三层开放模型见 [行为包开发指南](behaviors/dev-guide.md)）。

## 8. 作者须知

- **行为锁**：`tests/check_address_planning.py`、`tests/check_selection_arbiter.py`、`tests/check_env_selection.py`——改语义先改预期，别改断言迁就实现。
- **硬闸不开放**：可达范围（10 倍身高）、私有名约束、维度匹配是硬否决，不随行为包变化。
- **副本侧不做自动配对**：章节把地点地址写死，只用它筛「这一带」的地标，不做距离阈值（见 [dungeon/scene.md](dungeon/scene.md)）；「从 A 移动到 B」的移动叙述属展示层，另议。
