# 世界包制作：打包、清单与启用接管（面向作者）

> **这一篇回答什么问题**：把手上的素材打成一个 `.world.zip`、包里每个文件放在哪、
> `world.json` 怎么写、程序启用时按什么顺序接管，以及「启用后没生效」该往哪查。
> 只想装包 / 启停 / 删包，看 [README.md](README.md)。
>
> - **第一次做包**：§2 打包 → §3 包内布局 → §4 导入。
> - **手写或核对清单**：§11 参数表（全字段与成员核对）。
> - **排查接管问题**：§5 启用顺序、§6 命名空间、§13 作者须知。
>
> 直接相关：资源类型与信封 [../resources.md](../resources.md) · 注册地址与维度命名
> [../address_system.md](../address_system.md) · 话题表整表替换
> [../chat/lens.md](../chat/lens.md) §10。

## 1. 声明即接管

世界包是**一整套可搬迁的世界**：地标风格、描述风格、取材表、副本方案、行为包、挑战包、
话题表、小游戏，挑其中若干种打成一个 zip。清单里的 `resources` 声明这个包有哪些资源，
程序就按这份声明去核对磁盘，并决定启用期间接管哪些类型。

由此得出主线：**没声明的类型不接管**（启用期间照旧读自由目录），**声明了就是整类型
接管**（地标 / 描述风格按 §6 合并）。声明与接管依据是同一份文件，不存在第二处开关。

包在磁盘上是一个目录 `data/worlds/<world_id>/`，分享出去时压成 `<world_id>.world.zip`。
建完的包立刻就在这个目录里，但**启用之前不影响任何东西**；同名 `world_id` 不允许重复创建。

## 2. 打包：从当前世界创建

资源中心「世界包」右上角「＋ 新建」，两步。

**第一步填信息**：包名称（必填）、版本号（默认 `1.0`）、作者、简介。世界 ID 藏在
「高级 ▸」里——默认按包名派生（`world_` + 包名的 ASCII 片段，没有可用字符就随机 8 位），
你手填过之后就固定不再跟随包名。

**第二步选素材**，左边一列单选、右边一块多选（用 ▶ 在类型之间切换，每类都带全选 / 清空）：

| 位置 | 类型 | 说明 |
|---|---|---|
| 左栏下拉 | 取材表、行为包、话题表 | 每类最多一份，可以「<不配置>」 |
| 右栏列表 | 地标风格、描述风格、副本方案、挑战包、小游戏 | 想打几份打几份 |

至少选一种，否则「确定」不给过。几条打包时才生效的规则：

- **取材表按当时的完整搭配打包**：选中的组会先按回落规则补齐四张表，再整组快照进包——
  所以包里那份不依赖你本机的 `default` 组。
- **挑战包只拷 `.chal`，不带秘钥**：秘钥要随包分享，得手动把 `keys.json` 放进包内
  `challenges/` 目录（向导底部就写着这句）。
- **行为包只能一个**，并自动盖当前行为契约版本，所以启用时不会因为版本对不上而报警告。
- **世界维度是推导出来的**：程序读所选地标 / 描述风格的注册地址，把出现的维度名取并集
  写进清单 `worlds`。全都没注册地址时它留空——空的意思是「整类型接管」（§6），不是
  「什么都不接管」。

## 3. 包里长什么样

目录名即类型 id，清单 `world.json` 是唯一必需文件：

```
world.json
landmarks/<style>.csv                          # (+ <style>.addr.json、<style>.meta.json)
quips/<style>/{quips.csv, config.json}         # (+ <style>.addr.json、<style>.meta.json)
materials/<组>/{names,presets,personalities,news}.csv
scenarios/<id>/config.json
challenges/<name>.chal                         # 秘钥记录在包内 challenges/keys.json
behaviors/<pack>/*.py
topics/<table>                                 # 整表替换，主文件不带后缀
minigames/<id>/manifest.json
icon.png                                       # 封面，随目录打包自动带上，不进清单
```

清单里 `resources` 声明了「这个包有哪些资源」，程序就按这份声明去核对磁盘：声明了却
缺主文件，导入直接失败（取材表只要求组内有一张 CSV，因为缺席成员会回落）。反过来，包内
多放的东西不在核对范围里——这条在 §9 有下文。

旧版 `quips/<style>` 单文件布局不再接受，导入时会按「缺少 `quips.csv`」报错。

## 4. 导入：解包时的六道检查

导入依次做这些事，任何一步不过就整体放弃、不留半成品：

1. 能打开 zip、里面有 `world.json`、JSON 能解析；
2. 清单本身合法（§11 的字段规则）；
3. 声明的成员都在包里；
4. 目标 `data/worlds/<world_id>/` 不存在——已存在就拒绝，**不覆盖**，要先删掉旧包；
5. 逐个成员检查路径安全：绝对路径、Windows 盘符、带 `..` 的成员一律拒绝；
6. 解到临时目录，再读一遍清单确认没被掉包，然后整体搬到目标目录。

> 现状：导入和导出都只有服务层实现，资源中心还没有对应按钮。要装别人的包，走 §10 的
> 「手动部署」；要分享，也是手动压包。

## 5. 启用：程序按这个顺序接管

点卡片就是启用。启用时按这个顺序发生：

1. 重新校验清单（不合法就报错，什么都不改）；
2. 记住激活态；
3. 载入包内行为包（先清掉上一次的覆盖，再逐个模块注册）；
4. 装话题表：包声明了 `topics` 就整表替换，没声明或加载失败就回落到内置表；
5. 叠加包锁定的世界块设置（世界设定、种子、取材表名）；
6. 把 `active_world` 写进资源设置并落盘。

各类型的接管方式：

| 类型 | 启用期间 |
|---|---|
| 地标风格 / 描述风格 | 走命名空间合并（§6）；`selected_styles` / `selected_quip_styles` 收敛成「包内全列 + 仍可用的自由风格」 |
| 取材表 | 整类型接管；组内缺席的成员仍回落内置 `default`；当前这组不在包里时改取包内第一组 |
| 副本方案 | 整类型接管（默认方案除外） |
| 话题表 | 整表替换 |
| 行为包 | 运行时覆盖，一次只有一个 |
| 挑战包 / 小游戏 | 包内目录优先解析（挑战包秘钥读包内 `keys.json`） |

**停用**把自由设置整体读回来覆盖内存、摘掉 `active_world`、清掉行为覆盖、还原内置话题表。
包本身留在 `data/worlds/` 里不动，随时可以再启用。

程序每次启动都会按 `active_world` 恢复启用态；包坏了（清单被改坏、目录被删）只打印一条
警告并摘掉这个键，不拦启动。另外，**启用后改 `world.json` 不会即时生效**——清单在启用、
列表刷新和启动时读，改完请重新启用一次。

## 6. 命名空间：包内素材与自己的素材共存

只有带注册地址的两类（地标风格、描述风格）参与命名空间，规则看你清单里的 `worlds`：

| 清单 `worlds` | 你能看到的地标 / 描述风格 |
|---|---|
| 没启用包 | 全部自由目录里的风格 |
| 启用，`worlds` 为空 | **只有包内**（整类型接管，包外风格一律不可见） |
| 启用，`worlds` 非空 | 包内全部 + 自由目录里「与包内不同名、且注册地址维度不在声明里（或干脆没注册地址）」的风格 |

两条边界值得记住：

- **同名一律包内赢**。id 只做身份，没有「重名自动改名」这回事——自由目录里同名的风格
  在启用期间被遮蔽，停用后原样回来。
- **空 `worlds` 是「全接管」，不是「不接管」**。包里没带某个风格也一样：读取目录指向
  包目录，不会去自由目录找同名的。想让自己的素材陪着包一起用，就给包里的风格注册地址、
  把维度写进 `worlds`。

资源中心还有一条相关规则：**同一维度互斥**——已选风格里有一条带注册地址，两栏风格列表
就按那个维度筛，换维度时顺手剔掉不一致的已选风格（没注册地址的不受限）。

## 7. 删除与解散

删除入口只长在**启用中**的卡片上（「停用」「删除」两个按钮）；其它卡片点一下是启用。
所以想删一个没启用的包，先点它启用。

点「删除」会问一句：要不要把包内资源解散到自由资源？

- **解散**（是）：先停用 → 各类型资源搬回自由层 → 包锁定的设置并入你的自由设置 →
  删掉包目录；
- **直接删**（否）：停用，然后只删包目录，包里的东西一起没了；
- 取消：什么都不做。

解散时各类资源的去向：

| 类型 | 去向 |
|---|---|
| 地标风格 | 拷回 `data/packs/landmarks/`，`.addr.json` 跟着改名 |
| 描述风格 | 整目录拷回 `data/packs/quips/`（含 `config.json` 与你自己塞进去的文件） |
| 取材表 | 整组拷回 `data/static/materials/`，并把 `material_table` 指过去 |
| 副本方案 | 枚举包内方案目录（激活期间在包里新建的也会带走，默认方案跳过） |
| 挑战包 | 拷回 `data/packs/challenges/`，包内 `keys.json` 里的秘钥注册进本地 |
| 行为包 | 整目录拷回 `data/static/behaviors/` |
| 话题表 | 落成 `data/packs/topics/<table>`（之后还能被别的包带走） |
| 小游戏 | 整目录拷回 `data/packs/minigames/` |

**目标重名时自动改名**：先试原名，撞了就改成 `<原名>_<world_id>_<版本>`，还撞就继续
追加 `_2`、`_3`。信封按改名后的目标 id 写到新位置；目标已有信封时不覆盖——你那边原来
的信封优先。

## 8. 申领地址：注册表必须联网

打包时的 `worlds` 来自风格的注册地址，而地址是申领来的，所以顺带说清注册这件事。

注册表是 GitHub Gist 上的 `registry.json`（树形结构、申领规则见
[../address_system.md](../address_system.md) §10），客户端负责下载、缓存与查询：

- 本地缓存 `data/user/address_registry.json`，形状 `{data, fetched_at, gist_updated_at}`；
- **会下载的时机**：打开地址选择对话框时试一次（失败就用缓存）；地标编辑器展开子地址
  下拉时同样刷新一次；
- **注册必须当场联网成功**：点确定时重新下载最新注册表，地址还必须在表里申领过（规范化
  后逐字匹配），否则拒绝——离线一律不能注册；
- 启动程序、启用世界包都**不**触发下载；
- 离线时缓存照样能查、能搜、能看子地址，只是不能注册。

## 9. 内部实现

- **激活态落在资源设置里**：`active_world` 存在 `data/user/resource_settings.json`。副本
  子进程没有注册表也没有持久层，它直接读这个文件来定位包内小游戏与素材——不靠父进程
  传参，所以子进程里拿到的和主界面一致。
- **清单是原子写的**：清单坏掉，这个包的导入、启用、导出会一起失败，所以写盘用原子替换。
  读取侧每次都重新校验，不信任上次读到的内容。
- **导出就是重打包目录**：遍历包目录、按原相对路径写进 zip，所以 `icon.png`、你手动放
  进去的 `keys.json` 都会一起带走（默认落在 `data/worlds/<id>.world.zip`）。
- **导入先解到临时目录**：路径安全在解压前逐条检查，落地前再校验一次清单，任何异常回滚
  临时目录与目标目录。
- **包内多出来的目录会被列出来**：地标风格、描述风格、副本方案是按目录列举的，清单没
  声明的也会出现在资源列表里。但解散只搬清单声明的——只丢在包目录里不入清单的东西，
  删包时就跟着没了。

## 10. 拓展用法

界面上没写、但只动你自己数据的四件事：

- **手写清单补界面没有的字段**：向导只写名称、版本、作者、简介和资源清单；
  `traits`（世界观基调）、`language`、`app_min_version` 都能直接写进 `world.json`，
  校验只要求类型正确。
- **手动压包**：把 `data/worlds/<id>/` **整目录**压成 `<id>.world.zip`——zip 的根就是
  包根，`world.json` 要正好在根上，别多套一层文件夹。
- **手动部署**：别人的包解压到 `data/worlds/<目录名>/`，目录名必须**等于清单里的
  `world_id`**（启用时按 id 拼路径），否则会提示包不存在。这条路绕过了导入时的路径安全
  检查，只对信得过的来源用。
- **给包加封面**：包根放一张 `icon.png` 就行，资源中心卡片直接用它，清单不用改。

## 11. 参数表

`world.json` 的全部字段：

<details>
<summary>写清单或核对报错时展开（字段、取值与成员核对形状）</summary>

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format_version` | int | — | 清单版本，当前只认 `1` |
| `behavior_api` | int | — | 行为契约版本；省略按 1，与运行时不符只警告 |
| `world_id` | str | 是 | `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`，同时是部署目录名 |
| `name` | str | 是 | 显示名，非空 |
| `version` | str | — | 缺省 `1.0` |
| `author` / `description` | str | — | 署名与简介 |
| `traits` | str 列表 | — | 世界观基调，按 realistic / fantasy / anime / scifi 写（校验只要求非空字符串） |
| `language` | str | — | 主语言 |
| `app_min_version` | str | — | 建议的最低程序版本，仅供标注 |
| `created_at` | str | — | 创建时间，建包时自动写入 |
| `worlds` | str 列表 | — | 接管的地址维度；不重复、`^[A-Za-z0-9_]{1,48}$`；空 = 整类型接管 |
| `settings` | 对象 | — | 只允许世界块键，见下 |
| `resources` | 对象 | — | 键 = 类型 id，值为资源 id 列表 |

`settings` 只收这些键：`world_setting`（`appear` / `abs_giant` / `rel_giant`）、`seed`
（整数）、`selected_styles` / `selected_quip_styles` / `material_table`（表名，非空字符串；
只有当包拥有对应类型时才生效并锁住）。其他设置键写了会被判为清单非法。

`resources` 每类上限：取材表、行为包、话题表各 **1** 份，其余不限。资源 id 按类型规则
校验（行为包按 Python 标识符），大小写敏感。

成员核对形状（声明了就必须在包里）：

| 类型 | 包里必须有的成员 |
|---|---|
| `landmarks` | `landmarks/<id>.csv` |
| `quips` | `quips/<id>/quips.csv` |
| `materials` | `materials/<组>/` 下任意一张 `.csv` |
| `scenarios` | `scenarios/<id>/config.json` |
| `challenges` | `challenges/<id>.chal` |
| `behaviors` | `behaviors/<id>/` 下任意一个 `.py`（兼容旧的 `<id>.py` 单文件） |
| `topics` | `topics/<id>`（无后缀） |
| `minigames` | `minigames/<id>/manifest.json` |

</details>

## 12. 官方资源

发行版**不自带世界包**——首次启动 `data/worlds/` 是空的。官方提供的素材都以自由资源的
形式给出来（地标风格、描述风格、取材表、行为包、默认方案、两个小游戏等），清单见
[../resources.md](../resources.md) §14；想直接体验一次世界包，把内置素材按 §2 打一个包
就是最省事的做法。玩家拿到包之后怎么用，见 [README.md](README.md)。

## 13. 作者须知

<details>
<summary>改清单、调整目录、排查「启用后没生效」时对照</summary>

1. **清单是声明，也是接管依据**：`resources` 里没声明的类型，启用期间照旧读自由目录；
   声明了才接管，且接管就是整类型接管（地标 / 描述风格按 §6 合并）。
2. **`worlds` 与注册地址要对得上**：包内风格的 `.addr.json` 维度不在 `worlds` 里时，包
   列表的数据里会带一条警告（那个风格的地址维度没被声明）。这条检查已实现，界面还没把
   它显示出来，也不阻断启用——写清单时自己核对一遍更省事。
3. **`behavior_api` 不匹配只警告**：程序里创建的包自动盖当前版本；手写清单写高或写低都
   只提醒，不拦。
4. **包目录名就是 id**：手动部署时目录名与 `world_id` 不一致，启用会失败（程序按 id 拼
   目录路径）；想改 id 就得连目录名一起改。
5. **启用后改清单要重新启用**：内存里的激活态不会自己刷新。
6. **不要只把资源丢进包目录**：多出的地标 / 描述风格 / 方案会被列出来，但解散时不搬走，
   删包即失去。要留着就写进 `resources`。
7. **同名即遮蔽**：自由层与包内同名的风格，启用期间只认包内，没有改名机制。
8. **守卫**：`python tests/run_checks.py check_world_pack_worlds check_paths_active_world`
   （命名空间合并、激活态持久化与子进程读取）。

</details>
