# 角色演化：介入度、深度与行动点

> **这一篇回答什么问题**：她的介入度与破坏性为什么会慢慢往一个方向漂、报告和副本各推进多少、贴到边上之后为什么不会失控、行动点怎么花怎么回。
> - **普通玩家**：§1 认全她身上的几层数，§2～§3 看性格怎样决定走向，§4～§5 是边界与行动点。
> - **想调数值的作者**：§8 的公式折叠表、§9 的内置性格表、§10 的开放面，按需进。
>
> 相关页面：关掉游戏那段时间怎么结账 [character_time.md](character_time.md) · 报告里挑了什么地标 [report_selection.md](report_selection.md) · 章节触发器的演化修正 [dungeon/script.md](dungeon/script.md)。

> **三层术语**：**潜质**是她巨大化后可能暴露的底色（档案里的初始值），**深度**是潜质展开的速度（每单位步进深入多少），**介入度 / 破坏性**是她此刻表现出来的状态。三层不同层、不同写法，别互相代称。

## 1. 她身上的几层数

演化涉及的全部量按层排开，越往下越是「此刻的结果」：

| 层 | 术语 | 是什么 | 范围 |
|---|---|---|---|
| 日常性格 | 敏感值 / 重力 / 个性强度 | 性格常量（策略值由前两者派生，见 §2） | 前两个 **[-3, 3]**，第三个 **[0, 5]** |
| 巨大化潜质 | 介入潜质 / 破坏潜质 | 普通少女巨大化后会暴露多少底色 | 档案里的初始值 |
| 潜质展开 | 介入深度 / 破坏深度 | **每单位步进深入多少**；正数越陷越深，负数逐渐抽离 | 无固定上下限，靠 §4 的衰减管住 |
| 角色状态 | 介入度 / 破坏性 | 她此刻表现出多少 | 统一 **0.5 ~ 4.5** |
| 输入 | 步进 | 这段文本把故事推进了多少 | 每段一个值：报告按事件权重给，副本按段落类型给 |
| 资源 | 行动点 | 生成报告、进副本要花的点数 | **0 ~ 100**（自然回复到 100 封顶，返还可超） |

**深度不是「多深」，是「每步陷多快」**：`介入度 += 介入深度 × 步进`——步进越大、深度越深，这一步走得越远。所以同一个深度在平淡段落里推进得少、在高潮段落里推进得多。

**0 是有含义的**：潜质为 0 表示没有固定潜质，巨大化后随机演化，对应的深度滑块在面板上禁用。想让一个角色「天生没有偏向」，填 0 比填一个很小的数更准确。

**0.5 ~ 4.5 是所有路径共用的边界**：报告、副本、结局结算、负向演化，谁写介入度与破坏性都夹在这段里；副本结束写回角色时自然也不会越界。以前副本与角色各有一套边界，现在只剩这一套。

## 2. 性格的三个参数各管什么

创建角色时定的日常性格，决定她往哪边漂、漂得多快、贴边之后收不收得住。

- **敏感值**：只直接管**介入度**——报告 / 副本里的介入深度演化、地标切换、负向演化的介入深度步进、章节持续演化修正（属性是介入度时）。
- **重力**：同样四类场景，但管**破坏性**。两个参数是分开的，所以「爱插手但不爱破坏」这种性格是存在的。
- **个性强度**：三处调制——深度往初始值恢复的速度（`0.2 × 强度`）、每分钟行动点回复（`1 + 0.3 × 强度`）、不适应性衰减的折扣（`1 - 归一个性强度`）。强度越高的角色越「固执」：回得快、回得多、贴边也不肯收。
- **策略值**：由前两个参数加行动点算出来的派生值，`策略值 = 敏感值 × (1 - 归一行动点数) + 重力 × 归一个性强度`。行动点越少，介入度那一侧的权重越轻（她越没力气去插手）；个性越强，破坏性那一侧越重。它只用在两处：创建时贪婪判定生成的身高重映射，以及章节演化修正作用在**非介入度、非破坏性**属性上时。**负向演化的介入深度不走策略值**，由敏感值直接控制。

> 一个常见的误读：策略值是「她此刻的性格画像」，不是状态本身。它不推动介入度与破坏性，也不减少敏感值 / 重力的作用；面板上只作为描述行，不设滑块。

## 3. 介入度与破坏性什么时候会动

只在这五条路径上移动，每条推进的量不同：

**① 生成报告**。每一步按报告给出的步进推进：介入度先加上 `介入深度 × 步进`（夹取 0.5~4.5），然后介入深度减去 `步进 × 敏感值`、破坏深度减去 `步进 × 重力`，再让深度按个性强度往初始值恢复一点，最后叠加 §4 的不适应性衰减。**先扣除再恢复**是这一步的固定次序。

**② 进副本**。跟报告同构，只有次序反了：**先恢复深度，再推进介入度与破坏性**。差异出在步进上——副本的段步进按文本类型固定（background `0.02` 一路到 action `0.3`），方向由 AI 输出（±1）；章节的持续演化修正与触发器的限时效果会改这里的敏感倍率，倍率为 `强度 × (性格值 + 客观影响)`。**交互不直接加数值**：交互对介入度与破坏性的影响，一律由绑定触发器跳转到带演化修正的章节来实现。

**③ 地标切换**。切到常见地标：介入度 `+敏感值`；切到独特地标：介入度 `-敏感值`——地标越稀有，她越「收着」。破坏性到 3 以上时这条也生效：切到独特 `+重力`，切到常见 `-重力`。

**④ 闲置回落**。角色面板开着时，每分钟介入度与破坏性朝**潜质**回落一点（fraction `0.1`）：只有越过潜质时才回落，回落量是 `fraction × 初始深度`，不越过潜质，方向由初始深度的符号决定。没有设定潜质的角色不回落，停在原地。

**⑤ 载入时结账**。重新载入角色时按离开的时长批量推进介入度、破坏性与伤亡（含作息调制、72 小时明细），行动点也在这时补齐。这套结算的完整口径在 [character_time.md](character_time.md) §1，这里只说它同样受上面这些参数控制。

**负向演化**是藏在每条路径里的一步自检：行动点低于 **50** 时，每步额外推进一次，介入深度步进取 `-1 - 0.5 × 敏感值`、破坏深度步进取 `-1 - 0.5 × 重力`，介入度与破坏性按当前深度乘以这个步进平移，有变化就在演化表里追加一行。它也是唯一一处**敏感值直接决定步进**的地方。

<details>
<summary>演化公式的完整形态（想推一遍数值、或核对某次演化为什么是这个量时展开）</summary>

| 路径 | 公式 |
|---|---|
| 报告 | 介入度 `+= 介入深度 × 步进`；介入深度 `-= 步进 × 敏感值`、破坏深度 `-= 步进 × 重力`；深度 `+= (初始深度 - 深度) × 0.2 × 强度`；再乘 §4 衰减 |
| 副本 | 同上，但先恢复深度、后推进介入度与破坏性；步进按文本类型固定，方向 ±1 |
| 地标切换 | 常见：介入度 `+敏感值`；独特：介入度 `-敏感值`；破坏性 ≥ 3 时，独特 `+重力` / 常见 `-重力` |
| 闲置回落 | `fraction × 初始深度`（fraction = 0.1 / 分钟），不越过潜质 |
| 载入结账 | 本段步进 ≈ 活动基线 × `step_per_hour` × 作息系数 + 退出残留；伤亡按 `0.01 × 身高² × 步进 × 破坏性 × 环境因子 × log10(身高)` |
| 负向演化 | 介入深度步进 `-1 - 0.5 × 敏感值`，破坏深度步进 `-1 - 0.5 × 重力` |
| 不适应性衰减 | `深度 ×= 0.4 ^ (|步进| × (1 - 归一个性强度))` |

参数本身（`step_per_hour`、`exit_amp`、`recovery_*` 等）来自角色创建时的出身烙印，默认值与含义见 [character_time.md](character_time.md) §1 的折叠表——那份表是唯一的登记处，这里不重复。

</details>

## 4. 贴边之后：不适应性衰减

介入度或破坏性一旦到达 **0.5** 或 **4.5**（按当前值判断，报告、副本、负向演化三条路径都会传进来），对应深度每步乘一次 `0.4 ^ (|步进| × (1 - 归一个性强度))`。

它解决的问题很具体：深度是速率，贴着边界被反复「踢」很容易越滚越大，最后发散成离谱数值。这条衰减让深度在贴边期间指数级趋向 0——**越贴边越推不动**，等数值离开边界再自然恢复。个性强度越高衰减越弱，强度 5 时衰减为 0（见 §8 的已知边界）。它只衰减深度，不负责敏感值 / 重力的扣除；步进为负时取绝对值参与计算。

## 5. 行动点：怎么花、怎么回

- **消耗**：生成报告；进入副本（入口消耗由副本方案自己配）；地址切换按距离。
- **回复**：每分钟 `1 + 0.3 × 个性强度`，自然回复到 **100** 封顶。
- **返还**：副本结局返还、报告解锁部位返还。返还**没有上限**，只保证不低于 0——所以可以在进副本前把点数压得很低，再靠结局一次性拿回来。

行动点低于 50 时会触发 §3 的负向演化，这条阈值是「她开始没力气」的分界：点数越少，介入度与破坏性往下走的次数越多。

## 6. 内部实现

- **报告路径**的扣除与恢复由 `StateService.evolve_depths` 在介入度演化之后一次做完；副本路径在主公式 `dungeon/rules.py::EvolutionRules.evolve_attributes` 里，只有注入的 `StateService.decay_depths` 这一处受行为包影响。两条路径共用 0.5~4.5 的夹取，不再各自维护边界。
- **自定义属性不保存、不跟踪**：副本里临时加的属性每次开局重算，不进存档，也不参与演化记账。
- **载入结账的两层分工**：`offline.recover_plan` 只产出计划（行动点增量、结算后的介入度与破坏性、明细、步进、本次伤亡），`OfflineService.recover_offline` 负责写回与记演化行，展示文案交给 `offline.report_text`。行为包能改计划与文案，改不了执行与持久化；72 小时窗口与 2 小时精度是导出契约，固定不动。

## 7. 拓展用法

- **角色卡里的性格数据就是终身参数**：角色卡是普通 JSON，`personality_data` 决定创建时派生出的烙印（步进率、恢复速率、作息波动等）。想给同一角色换一套手感，改这一段再导入即可，不必在界面上一点点试；导入后新角色沿用新烙印，已在档的角色不受影响。
- **先看行为包会把这套数值改成什么样**：`python developer_tools/evolution_dump.py --pack <行为包>` 会先把包加载进演化运行时再模拟，输出与基线并排对比；报告里另有一节列出该包覆盖了哪些演化钩子（覆盖为 0 时直接点明结果应与基线一致）。

## 8. 参数表

<details>
<summary>模拟已验证的动态特性（调参前先读，免得把正常现象当 bug 查）</summary>

以下结论来自 `developer_tools/evolution_dump.py` 的批量模拟：UI 参数范围内（含角点）加上 `data/static/personalities/default.csv` 的全部性格，对比「长期点数不足」与「点数适中」两种消耗习惯。

1. **深度平衡点**：无边界干涉时约为 `初始深度 - 步进 × 敏感值 / 恢复率`。敏感值为正 → 介入深度往下漂 → 介入度偏低；为负则反过来。
2. **不适应性衰减有效**：贴边时深度几何收敛，配合统一夹取，UI 参数范围内深度峰值实测 ≤ 10，无发散、无 NaN / Inf。
3. **已知边界**：个性强度 5 时衰减为 0，全正角点在「长期点数不足」档会贴着 0.5 驻留（负向演化常态化）。要消除可以给强度 5 留一个最小衰减率。
4. **点数适中档**（负向演化触发率 < 1%）：无贴边死锁；深度在 0 附近有一个有界极限环（恢复 ↔ 衰减 ↔ 扣除互相拉锯，幅度 ≤ 几个深度单位），介入度正常游走。
5. **副本写回无越界**：介入度与破坏性统一夹取后，副本结束时的角色数值必然在 0.5~4.5 内。

模拟命令：

```
python developer_tools/evolution_dump.py                      # 角点 + 默认性格表，两种消耗习惯
python developer_tools/evolution_dump.py --group corners       # 只跑角点
python developer_tools/evolution_dump.py --group table --table default
python developer_tools/evolution_dump.py --only corner_all_pos,温柔
python developer_tools/evolution_dump.py --steps 2000 --profile ap_moderate
python developer_tools/evolution_dump.py --pack my_pack        # 带行为包（也可给目录 / .py 路径）
python developer_tools/evolution_dump.py --list-packs          # 有哪些行为包与性格表
```

输出写到 `developer_tools/_out/evolution/<消耗习惯>/`（带行为包时再嵌一层 `pack_<名>/`）：每角色跟踪图 + 总览图 + 报告。改过演化公式后建议跑一轮对照上面五条。

</details>

## 9. 官方资源

内置性格表在 `data/static/personalities/`，`default.csv` 是默认表，模拟工具的 `--group table` 会逐条跑这张表里的真实性格。出身烙印的参数登记在 [character_time.md](character_time.md) §1，两者合起来才是「她为什么这样动」的完整来源。

## 10. 作者须知

- **开放面**：报告路径用到的 `StateService` 深度方法（`evolve_depths` / `decay_depths` / `nudge_depths`）全部可覆盖，清单见 [hooks-character.md](behaviors/hooks-character.md)；副本演化主公式**没有**行为钩子，只通过注入的 `decay_depths` 受影响。
- **不开放的部分**：0.5~4.5 的夹取、72 小时 / 2 小时窗口、烙印参数的运行时改写。行为包改的是策略与参数值，不改边界与口径。
- **改完怎么验**：先跑 §8 的模拟对照五条结论，再跑 `python tests/check_report_engine.py`（报告侧推进）与 `python tests/check_model_tuning.py`（烙印派生）；改到公式本身时，同步更新 §8 的结论。
- **术语对齐**：代码侧字段是 `Personality.depth_intrusion` / `depth_destruction`，状态侧快照读 `current_depth_*`；钩子名随术语改过（`evolve_step_rates` → `evolve_depths`），旧名不再生效。写玩家文案时查 `docs/terminology.md`（潜质 / 深度 / 度 三层，旧称「介入度步长」已停用）。
