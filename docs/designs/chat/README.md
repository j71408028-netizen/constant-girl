# 聊天机制：身份、话题与三轴坐标

> **这一篇回答什么问题**：她和「某个人」聊天时此刻适合聊什么、为什么同一个人换个身份她就
> 像不认识你、聊天又凭什么反过来改变世界。
> - **普通玩家**：看 **§1～§2**（聊天是什么样、身份意味着什么）与 **§5**（话题怎么开始、
>   怎么结束、为什么不回）。
> - **资源作者**：**§9** 的两条用户数据用法、**§10** 的话题类型全表、**§12** 世界包替换
>   话题表的契约。
> - **想调手感或改代码**：**§3～§4** 的规则与 **§8** 的实现说明。
>
> 相关页面：某类话题下 AI 知道什么 [lens.md](lens.md) · 演化坐标与深度
> [character_evolution.md](../character_evolution.md) · 消息协议与投递节奏
> `docs/dev/chat_delivery.md`。

一句话：聊天按**玩家身份**拆成互不相通的线程；每条线程用**好感、紧张度、状态**三轴筛选
**话题类型**；AI 在候选类型里决定聊什么，并在回复后最多执行**一个世界效果**。

```text
玩家身份 identity_id
      │  (giantess_id, identity_id) → 一条线程：消息 / 好感 / 记忆 / 话题 / 关系
      ▼
三轴坐标 好感 · 紧张度 · 状态      ← 由领域事实派生，AI 看不到数值
      ▼
话题类型候选（半径过滤 + 重复惩罚，最多 5 个）
      ▼
AI 决策：继续 / 开新话题 / 切换 / 结束 / 已读不回
      ├─ 消息（1~4 条 + 投递节奏）
      ├─ ops（好感、行动点、称呼）
      └─ 至多一个 effect ──→ 改世界事实 ──→ 下一轮坐标变化
```

## 1. 一次聊天里你看到什么

打开对话框，你看到的是「她在回你」，但背后发生的事分三层：

- **她在挑话题，而不是在回答**。服务层先按她此刻的状态给出一小组「话题类型」（最多 5 个），
  AI 从中选一个，或者继续当前话题、切到另一个、直接结束。你看到的开场白、追问、冷场，都是
  这一步的结果。
- **回复不是一次到齐**。一轮可能来 1～4 条，按「读消息 → 打字 → 发送」的节奏陆续出现；
  沉默也是一条合法结果——她读了不回，但这一轮该记的账照记。
- **聊天会反过来动世界**。某些回复里带有至多一个「世界效果」：补一句她对自身的描述，或者
  让介入深度 / 破坏深度轻轻挪一点。这是聊天唯一能改变游戏状态的通道。

三轴（好感、紧张度、状态）不是给 AI 优化的数值，而是**服务层决定「此刻提供哪些话题类型」**
的依据；AI 只看到四档定性描述。这条边界是整套机制的核心，改代码时不要破。

## 2. 身份与线程：换一个身份就是换一个人

你可以拥有多个**身份**（马甲）。对角色而言它们是不同的人：她不共享消息、记忆、话题、
好感或关系，也不知道背后是同一个玩家。

| 数据 | 作用域 |
|---|---|
| 好感 `attitude`、消息、记忆、称呼、未读、最后活跃 | 线程（角色 × 身份） |
| 话题列表 / 活跃话题 / 已消费经历事件 / 关系认知 `Relationship` | 线程 |
| 聊天习惯 `ChatParams`、状态 `size_state` | 角色 |
| 世界态势 `world_stance`、事件压力 | 世界（各线程读同一份） |
| 世界效果 | 角色 / 世界；日志记在线程里 |

- 身份列表在 `data/user/identities.json`，默认身份恒在且排第一；新建身份自动成为当前身份。
  数量上限 **12**，名字最长 **24** 字。
- 每条线程单独存档：`data/archives/<giantess_id>/chats/<identity_id>.json`。旧版单个
  `chat.json` 按默认身份读取，只回退、不迁移也不删除。
- 未读按线程统计；角色卡上的徽标是各线程之和，**只是显示层聚合**，域内仍然互相隔离。

> 世界是共享的：换身份不会重置世界态势与事件压力，所以她对你这个身份紧张，不代表对另一个
> 身份也紧张——但世界的整体气氛两边一样。

## 3. 三轴坐标：她此刻适合聊什么

坐标由纯函数派生，话题开始时算一次并存进话题作为快照；本轮交流产生的好感变化与世界效果
只影响**下一轮**。

| 轴 | 含义 | 存盘 |
|---|---|---|
| 好感 `affection` | 亲近程度，`(attitude + 100) / 200`，只由聊天里的好感操作改变 | 是（`attitude`） |
| 紧张度 `tension` | 世界如何对待巨大娘 + 她如何看待当前这个身份 | 否，派生 |
| 状态 `size_state` | 她此刻对自身巨大化的接纳程度（高 = 接纳） | 否，派生 |

三轴的取值都在 `0～1`。公式、权重与衰减在 §8；这里只要记住两个手感：

- **状态大部分时间偏高**，只有坐标贴边或行动点吃紧时才明显下沉。低状态意味着「不适 / 危机」
  ——这时能选的话题类型少而重。
- **AI 看到的只有四档定性描述**（好感四档、紧张度四档、状态四档）。坐标原值、类型坐标与
  半径都不进提示词，避免 AI 把数值当台词或反向刷分。

## 4. 话题类型：坐标上的格点

每个话题类型在坐标上有一个位置和一个半径，外加三样东西：注意什么（`frame`）、怎么打字
（`prompt`）、能知道什么（信息视角，见 [lens.md](lens.md)）。这三样都写在同一条定义里，
增删一个话题只动一处。

选择规则：

- 只保留**三轴距离 ≤ 该类型半径**的类型；半径默认 `0.35`，可按类型单独设。坐标相近或
  完全重叠时多个类型同时入候选，**不强制选最近的**。
- 排序看「距离 + 重复惩罚」，再看优先级。重复惩罚对最近用过的类型按 `0.08` 起、逐次
  半衰叠加——刚聊过的话题会退到后面。
- 注入提示词的候选**最多 5 个**，每行给名称、一句信息预告（`focus`）与一句姿态（`frame`
  的第一小句）。所以 AI 选类型的同时，等于选了一套信息与一副姿态。
- 无候选时回退 `daily`；AI 给出的类型不在候选里就回退第一个候选。
- 当前话题的坐标超出它自己的半径时，提示词会告诉 AI 可以结束或换类型。

## 5. 继续、切换、结束与沉默

协议里话题动作只有 `continue / start / switch / end` 四种，全部由 AI 判断，不做关键词
匹配。你看到的表现是：

- **聊到一半忽然收尾**：同一话题聊满 **20 轮**由服务端强制收束（标 `stale`）。
- **放了一天再回来，话题已经关了**：进行中的话题超过 **6 小时**没续聊，下次打开聊天时
  直接收束，不需要 AI 参与。
- **她读了不回**：回复为空但给了理由，就是「已读不回」。这一轮的好感变化、记忆、世界效果
  与话题状态照常结算，只是不排队发消息。
- **同一个类型再次出现是新的开始**：类型复用不会复活旧话题，重新计时计轮数，旧的保持结束。

## 6. 关系认知：她认为对面是谁

每条线程带一份关系认知（`kind` / `note` / 起始时间 / 更新时间），默认「陌生人」。它回答的
是「她认为对面是谁」，与好感可以背离：高好感也可能把你当猎物，低好感也可能把你当同类。

- AI 可以提出更新，但只在话题**结束或切换**时落地；聊到一半、已读不回、被强制收束都丢弃。
- 关系档位只能沿白名单**逐级**变化，不能一轮从陌生人跳到恋人 / 敌人；非法更新连同备注
  整条丢弃。备注单独更新也可以，超长截断到 **200 字**。
- 每个身份有 **72 小时**冷却，冷却期内再次提交被忽略。
- 它只影响**下一次**话题选择时的紧张度，不改变当前话题——这是「AI 不能直接写紧张度」的
  配套约束：它只能改认知，紧张度仍由公式算。

## 7. 世界效果：聊天能改什么

AI 只能输出「用哪个工具 + 参数」，服务层校验、夹取、执行并留日志。当前开放两个：

| 工具 | 作用 |
|---|---|
| `self_view` | 往她的可见自我介绍里追加一句，单条 ≤ 500 字，重复内容不重复追加 |
| `step_nudge` | 让介入深度或破坏深度朝某个方向挪一点，单次约 `±0.02`，接近上限时衰减 |

规则是「每轮最多一个」：给成数组视为多个，整条丢弃；未知工具或非法参数只记失败日志，
不重试、也不回滚已经生成的回复。每次执行（含失败）追加一条记录到线程里，保留最近 50 条。

**没有任何直接改紧张度或状态的工具**——它们只能由世界事实派生。反馈回路靠四条压住：
每轮一个、单次幅度极小、事件压力按时间衰减、聊天来源的事件在紧张度里低权重。

## 8. 内部实现

- **紧张度**：`clamp(0.6 × world_stance + 0.4 × identity_offset + 0.3 × event_pressure)`。
  `world_stance` 读 `settings.json` 的 `world_stance`（`worship 0.10 / accept 0.25 /
  coexist 0.45 / alert 0.70 / hostile 0.90`，缺省 `coexist`）；`identity_offset` 按关系档位
  取 `lover -0.15 / close -0.10 / friend -0.05 / stranger +0.05 / rival +0.15 /
  enemy +0.25`；`event_pressure` 扫最近 50 行演化记录与 7 天窗口，按伤亡增量与坐标位移
  计权，排除纯闲置衰减行，旧聊天来源按 `0.25` 低权重计入，求和后按 48 小时半衰。
- **状态**：`clamp(0.5 + 0.4 × resilience − 0.5 × edge − 0.5 × ap_deficit)`。`resilience`
  是归一个性强度（缺性格时 `0.6`），`edge` 取介入度 / 破坏性里更贴边的那个（软边界 `0.5`），
  `ap_deficit` 以行动点 50 为线。
- **一轮的落地顺序固定**：`ops → memory_note → effect → 话题状态机 → 关系认知 → 保存
  线程（有改动时连角色一起）`。坐标快照取在 `ops` / `effect` 之前，所以效果从下一轮才影响
  话题选择。
- **调参位置**：坐标公式在 `services/chat/coordinates.py`（`TENSION_W_*`、`TENSION_TAU_HOURS`、
  `AP_LOW`、`EDGE_MARGIN`）；话题类型与轮数常量在 `services/chat/topic_kinds.py` 与
  `services/chat/__init__.py`（`MAX_TOPIC_TURNS`、`TOPIC_EXPIRE_HOURS`、
  `IDENTITY_TRANSITIONS`）；效果幅度在 `services/chat/effects.py`。

## 9. 拓展用法

- **改 `settings.json` 的 `world_stance`**：不用碰代码就能整体调世界对她的敌意——`hostile`
  下紧张度整体抬高，`spar` / `guard` 更容易出现；`worship` 下则长期偏松。
- **用世界包整表替换话题表**：`topics` 是一种资源类型，世界包带一张自己的 JSON 表，激活
  期间替换掉内置表，停用后还原（契约见 §12）。想给一个世界配一整套专属话题，这是唯一
  不需要改程序的做法。
- **把身份当不同的关系线来养**：多个身份共享同一个世界态势，但各自的好感、记忆与关系认知
  完全独立，可以同时观察「她对陌生人和对熟人分别是什么样」。

## 11. 官方资源

内置一张 **18 个话题类型**的默认表（§4 的两张表就是它的全部内容），表 id 为 `default`。
没有同名资源文件时它就指向代码里的内置表，所以「打包当前话题表」永远有东西可选，不必为了
打包先往用户目录写文件。

内置表不进资源索引：它没有磁盘载荷，算不出内容指纹；要发布就先落盘成文件。

## 12. 作者须知

<details>
<summary>世界包替换话题表的契约与已知边界（做话题资源或排查聊天异常时展开）</summary>

- **容器形状**：一份 JSON 数组，元素形状与「导出话题表」一致（`topic_kind_to_dict` 的
  输出），主文件**不带后缀**；激活时装成生效表，卸载 / 解散时还原内置表。
- **加载失败只打印并回退**：不影响包内其它资源，也不会让聊天开不了局。
- **校验分两层**：结构层查 id 重复、缺 `frame` / `focus`、`opens` / `denies` 自相矛盾；
  字段层查引用的存档字段是否已注册（漏注册不会静默丢弃）。
- **别在会话中途换表**：同一轮里两次取表可能拿到不同内容，只在包加载时换。
- **带 `virtual` 的条目**（无话题时的兜底视角）会被摘出来，不参与候选；「整表导出再整表
  导入」可以原样往返。
- **行为包覆盖未做**：`chat.*` 钩子要等类型注册表与效果接口稳定后才加，现在不 bump
  行为包 API 版本；能改的措辞与节奏见 `docs/designs/behaviors/hooks-chat.md` 的契约页。
- **效果工具只两个**：`move` / `casualty` 后置；`cooldown` 字段已预留但暂未生效；没有
  任何制裁类通道，对抗向只保留 `spar` 与 `guard`。
- **个人状态不单独成类型**：疼痛、不适、困倦是状态轴与体裁的取值，并入 `body` / `reflect`
  的注意力框架，或交给投递节奏（短回复、间隔长）；告别与已读不回属于话题生命周期。
- **跨身份认知不做**：她不会知道 A 和 B 是同一个人。

</details>
