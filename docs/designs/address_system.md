# 地址系统

> **这一篇回答什么问题**：地标风格、描述风格与独特地标怎么登记地理位置、
> 报告凭什么让「同一张地图」上的内容接续叙述、想注册地址该怎么操作。
> 前半是玩家向全景；从「作者操作规程」起是资源作者与维护者的查表部分。

## 1. 全景（玩家向）

地址系统给地标风格、描述风格和独特地标登记一个地理位置；地址按
「维度 → 一级 → 二级 → 三级地域」组织，同一维度下的内容共用一张地图。

报告生成时，程序只让距离足够近的地标和描述接续叙述。所以她走过的地方
会像在同一张地图上，而不是随机拼贴：近距离的地标先出现，远处的、对不上的
地址不会被硬塞进同一份报告。

| 现象 | 背后发生了什么 |
|---|---|
| 报告里的地标按距离出现 | 角色当前位置与地标地址配对成功才可达 |
| 不同风格能拼进同一份报告 | 这些风格共享同一个维度，即同一张地图 |
| 描述只配到「覆盖」当前地点的风格 | 描述风格的注册地址必须覆盖地标地址才配对 |
| 某个地标仍出现，但标着「定位精度不足」 | 距离上界超过身高 10 倍，可能到得去也可能到不去 |
| 进副本时提示无法进入 | 方案声明了「方案地址 + 最大距离」，角色当前位置不满足 |

玩家需要做的：

- **通常什么都不用做。** 地址由资源作者申领、注册好之后自动生效。
- 想自己调**独特地标**的地址：在地标编辑对话框的「地址(可选)」里填写
  （见 §2.3）；双击地址框可以浏览已申领的子地址并点选回填。
- 地址留空：独特地标跟随所属风格的地址；均值地标不参与地址规则，到处可用。
- 副本准入由方案作者设置；进不去时，多半是角色当前所在的位置离方案地址太远。

离线与安全：

- 查看、选择本地缓存里的地址不需要联网，已有地址也照常参与报告生成；
  程序内**注册 / 修改**地址必须联网（点「确定」时重新下载最新注册表并校验）。
- 地址只影响筛选与配对，不执行任何代码。申领信息（`owner`、`claimed_at` 等）
  写入公开注册表，会把你在注册表中填写的署名公开。

报告如何用地址挑选地标与描述：[report_selection.md](report_selection.md)。

## 2. 作者操作规程

| 步骤 | 在哪里做 | 做什么 |
|------|----------|-------|
| 1. 申领 | GitHub Gist 仓库（网页编辑） | 声明“这个地址由我创建并负责”，写入注册表 |
| 2. 注册 | 程序内（文本管理器 / 地标对话框） | 把风格或地标绑定到已申领的地址 |
| 3. 生效 | 生成内容时 | 程序按配对与距离规则自动筛选地标、描述 |

**核心规则**：

- 申领在仓库中手工完成，程序内**不能**申领新地址；
- 程序内**注册**必须联网——每次点"确定"都会重新下载最新注册表，且只能
  注册其中已申领的地址。离线时可以查询本地缓存或清空注册的地址，但不能注册；
- 地址留空：独特地标视为继承所属风格的注册地址；均值地标视为未注册，
  到处可用、不参与任何地址规则。

在线注册表：<https://gist.github.com/j71408028-netizen/da0b6204e57a411462f2d72e3e0f1997>

### 2.1 第 1 步：申领地址（在仓库中，需要新增地址时才做）

1. 打开上面的 Gist 链接，编辑其中的 `registry.json`（需发送请求）；
2. 按树形结构（`worlds` → `regions` → `regions` …）追加节点，每个节点写上
   `description`、`owner`、`claimed_at` 等申领信息（格式见 §5）；
3. 保存提交。之后在程序中点"刷新"即可看到新申领的地址。

### 2.2 第 2 步：为风格注册地址

适用对象：文本管理器中的**地标风格**和**描述风格**（两者都有"📍地址"按钮）。

1. 打开文本管理页，选中要操作的风格；
2. 选择地址，两种方式任选：
   - **级联选择**：从上到下依次选 维度 → 一级地域 → 二级地域 → 三级地域，
     每级只列出注册表中已申领的选项；某级选"（不选此级，止于上一级）"表示
     地址到上一级为止；
   - **搜索**：在"序列化地址"输入框中输入，可按地址、描述、申领人过滤，
     点选结果后级联选择会自动联动。
3. 点"确定"保存。程序会联网下载最新注册表并校验该地址已申领，否则拒绝；
   若正在离线状态，会提示"离线，无法注册"。
4. 如需解除绑定，点"消除"再"确定"（无需联网）。消除后该风格不再参与地址规则。

⚠ **注意**：更改地标风格的注册地址后，原先基于旧地址组合出来的各地标地址
会失效（对话框中会给出警告），保存后请检查各地标的"地址(可选)"字段。

### 2.3 第 3 步：为独特地标填地址

在**地标编辑对话框**的"地址(可选)"中填写：

- **风格已注册地址时**：只填风格地址之下的剩余级别，可写一级 `East`
  或多级 `East-3`。例如风格注册到 `TH-GSK1`，地标在东部 3 号单元，
  就填 `East-3`。也接受完整地址 `1e4_2e3_2e2@TH-GSK1-East-3`
  （必须同维度且位于风格地址之内）。
- **风格未注册地址时**：填写完整地址（含维度和绝对规模），例如
  `1e4_2e3_2e2@TH-GSK1-East-3`。
- **双击地址框**：弹出下拉列表，列出注册表中该风格地址下的全部**已申领
  子地址**（含各级细度和描述），点选即回填。后台会联网刷新；离线时使用
  本地缓存。
  - 候选按地标尺寸自动过滤：最细单元边长小于地标尺寸的子地址会**置灰
    标记为"不推荐"**；若仍想使用，需手动输入地址。
  - 修改"尺寸(米)"会实时刷新候选的推荐状态。
- 地址留空：独特地标继承所属风格的注册地址；均值地标不参与地址规则。
  均值地标若填写了地址，则和独特地标一样参与筛选。

生成时程序把风格注册地址与地标地址组合成地标的完整地址（组合规则见 §3），
再按 §4 的口径筛选与配对；描述配对覆盖分层在报告选取中的完整用法见
[report_selection.md](report_selection.md)。

### 2.4 进入副本时的地址准入

副本方案可以声明「入口地址 + 最大距离」，字段与判定口径见
[dungeon/admission.md](dungeon/admission.md)：角色当前位置与入口地址必须同维度，
且距离区间的**上界**不超过上限（位置越粗，上界越大），否则无法进入；
角色没有地址时不参与地址准入。入口地址是主世界里的门，与副本内章节的取景地址
（[dungeon/scene.md](dungeon/scene.md)）是两回事。

## 3. 地址格式与组合

### 3.1 地址格式

```
<绝对规模>@ [<私有名或*>!]<维度>-<一级地域>-<二级地域>-<三级地域>
```

- **绝对规模**：以 `_` 分隔的 3 个数字，按 一级/二级/三级 给出该级单元的
  边长（米），如 `1e5_5e3_1e2` = 一级 100 km、二级 5 km、三级 100 m。
  包含地域段时必须提供；纯维度地址可省略。
- **约束段**（`@` 与 `!` 之间，可省）：
  - 完全没有 `@...!` 段 → 不与任何带约束的地址匹配（仅用于无约束地址）；
  - `@!` 或 `@*!` → 不指定私有名（规模一致性由地址树保证）；
  - `@abc!` → 要求私有名恰为 `abc`。
- **维度**：字母/数字/下划线，1~48 字符。
- **地域 id**：每级字母/数字/下划线，1~16 字符；最多三级（整个地址最多
  维度 + 3 段）。

示例：`1e5_5e3_1e2@abc!ea1-1-2` = 一级 100 km、二级 5 km、三级 100 m，
私有名 `abc`，维度 `ea1`，一级地域 `1`，二级地域 `2`。

### 3.2 风格注册地址与地标注册地址的组合

- **风格注册地址**：注册该风格所在的最上面若干级（维度必填）。
- **地标注册地址**：补在风格注册级别之下的剩余级别；风格未注册时填完整地址。
- **组合规则**：
  - 规模取"更细一方胜出"——地标带绝对规模时覆写风格的规模；
  - 私有名取先声明的一方（风格在前，地标覆写无效）；双方都声明具体
    私有名且不同时，组合失败；
  - 地域 id 取风格前缀 + 地标多余的后缀（公共前缀去重）；
  - 维度不同、地标地址不在风格地址之内（分支分叉）、层级超过三级时都会报错，
    该地标不参与本次地址规划，并在规划结果里记录诊断；不会静默退化成
    “无地址、到处可用”。

## 4. 配对与距离规则

- **判定入口**：配对 / 覆盖 / 距离 / 私有名约束由 `core.address_model.relate`
  一次算清（`AddressRelation`：空间关系 kind、距离区间、chunk_ok）；生成端
  （地标可达、描述配对）与副本准入都从这里取口径。
- **配对**：只比较地域序列——同址或互相包含即可配对；规模一致性由地址树
  保证。私有名约束仍有效：一方声明了私有名时，另一方必须声明相同私有名。
- **距离**：同址 → 0；目标包含角色位置 → 0；角色位置包含目标 → 区间
  `[0, 角色位置最小单元边长]`；否则取共同前缀之后**首个分歧级**，距离 =
  双方在该级边长的平均值。
- 维度不同 → 不可达。
- 角色位置无法解析时，地址系统给出 `invalid_position`，不静默重新锚定；
  地标地址存在但无法与风格组合时，给出 `invalid_address`，不静默当作未注册。
- 在报告进行过程中，角色位置将不断更新为最后到达的最详细地址。新地标的地址
  与角色位置间的距离在一定范围内，才视为可达；距离上界超出 10 倍身高的地标
  仍可能被选中，但标记“定位精度不足”。
- **描述配对**：描述风格的注册地址必须**覆盖**地标地址（描述风格更粗或同址），
  而不是像地标之间那样反向包含也算配对；覆盖分层（同址 > 覆盖 > 未注册）的
  用法见 [report_selection.md](report_selection.md)。

## 5. 注册表：registry.json

### 5.1 树形式（推荐）

```json
{
  "version": 2,
  "worlds": {
    "TH": {
      "description": "东方Project", "owner": "紫", "claimed_at": "2026-09-05",
      "regions": {
        "GSK1": {
          "scale": ["1e4", "2e3", "5e2"],
          "description": "幻想乡腹地",
          "regions": {
            "East": {
              "description": "幻想乡东部区域",
              "regions": {
                "hrjj": {"scale": ["3e2"], "description": "博丽神社"}
              }
            }
          }
        }
      }
    }
  }
}
```

- 节点字段：`description` / `owner` / `claimed_at` 为申领信息；`scale` 为
  该级申领的规模数组（个数规则见下）；`chunk` 为可选私有名；`regions` 为
  下一级地域。维度节点本身也是申领记录（可注册纯维度地址，无规模）。
- **申领规模规则**：一级地域**必须**带 3 个规模；二级地域可选带 2 个
  （覆写该分支的二/三级边长）；三级地域可选带 1 个（覆写三级边长）；
  未覆写的级别沿路径继承上一级。因此同一分支内的规模一致性由树结构保证，
  不同分支允许不同规模。
- **私有名不参与覆写**：只取路径上最先声明的值，子地址的覆写无效。若某
  私有名的管理者希望在其他私有名的语境下继续添加，应申领一个平行地址。
- 不合法的节点（规模个数错误、id 不合法等）会被程序跳过，并在状态行提示。

### 5.2 旧扁平格式（兼容）

列表式：

```json
{"version": 1,
 "addresses": [{"address": "1e4_2e3_2e2@TH-GSK1-East-hrjj", "description": "博丽神社",
                "owner": "紫", "claimed_at": "2026-09-05"}]}
```

映射式：`{"1e4_2e3_2e2@TH-GSK1-East-hrjj": "博丽神社"}`。

### 5.3 命名规范（推荐）

- 维度：大写字母缩写；
- 一级地域：大写字母缩写 + 数字；
- 二级地域：首字母大写完整词；
- 三级地域：小写字母缩写与数字。

同一地域下的直接子地域名称不应重名。
