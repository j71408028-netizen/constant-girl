# 地址系统

> **这一篇回答什么问题**：她走过的地方为什么能像在同一张地图上接续、报告凭什么把「近的
> 地标」和「对得上的描述」挑出来、想给地标或风格登记地址时该怎么做。
> - **普通玩家**：看 **§1～§4** 就够——地址在游戏里起什么作用、你唯一需要动手的地方
>   （§5 给地标填地址）。
> - **资源作者 / 注册表维护者**：**§6** 注册风格地址、**§7** 申领新地址、**§12** 契约。
> - **想改判定逻辑的开发者**：**§8** 与 **§10**。
>
> 相关页面：报告怎么挑地标与描述 [report_selection.md](report_selection.md) · 副本门口的
> 地址条件 [dungeon/admission.md](dungeon/admission.md) · 副本内章节的取景地址
> [dungeon/scene.md](dungeon/scene.md)。

地址系统给地标风格、描述风格和独特地标登记一个地理位置。地址按「维度 → 一级 → 二级 →
三级地域」组织，**同一维度下的内容共用一张地图**：在同一个维度里，程序才知道两个地方
离得远还是近。

## 1. 地址在游戏里做什么

你几乎不会直接看到「地址」这两个字，看到的是它的后果：

| 你看到的现象 | 背后发生了什么 |
|---|---|
| 报告里的地标由近到远出现 | 只有和角色当前位置配得上的地标才可达 |
| 不同风格能拼进同一份报告 | 这些风格注册在同一个维度，即同一张地图 |
| 描述只配到「覆盖」当前地点的风格 | 描述风格的注册地址必须覆盖地标地址 |
| 某个地标出现了，但标着「定位精度不足」 | 距离上界超过身高 10 倍，可能到得了也可能到不了 |
| 进副本时提示无法进入 | 方案声明了「入口地址 + 最大距离」，她当前位置不满足 |

玩家通常**什么都不用做**：地址由资源作者申领并注册好，装进来就自动生效。需要你动手的只有
一种情况——某个**独特地标**的地址要自己调（§5），其余的规则都是给作者与维护者看的。

> 地址只影响筛选与配对，不执行任何代码。查看、选择本地缓存里的地址不需要联网；在程序内
> **注册 / 修改**地址必须联网——点「确定」时会重新下载最新注册表并校验。

## 2. 一张地图怎么分层

一个地址由三段组成：**绝对规模**（每级单元多大）、**维度**（哪张地图）、**地域路径**（在这
张地图的哪一支）。地域最多三级，所以「哪里」的精度也最多三级：

- 知道到一级：可能是一整片区域，距离只能给个区间；
- 知道到三级：通常就是一个具体地点，距离接近精确值。

**精度不是玄学，是判定口径的一部分**：位置越粗，距离的区间越宽，判定越保守（§3 与 §8）。
这也是为什么「她明明就在附近却进不去」——她的位置可能只记录到一级，最坏情况超过了门限。

规模与私有名还有两条规则，等真正要写地址时再看 §10：规模取「更细的一方胜出」，私有名取
「先声明的一方」。

## 3. 报告怎么用地址

报告每次要选地标、配描述，地址在这里做两件事。

**选地标**：只看地域序列——同址或互相包含就能配对。距离按下面四种情况算：

| 关系 | 距离 |
|---|---|
| 同址 | `0` |
| 目标包含角色位置（地标比她的位置更粗） | `0` |
| 角色位置包含目标（她知道自己在哪片区域，地标在里面） | `0` 到「角色位置最小单元边长」的区间 |
| 两侧在某级分叉 | 该级双方单元边长的平均值 |

维度不同就是不可达，不会硬塞。距离上界超过身高 10 倍的地标仍可能被选中，但会标「定位
精度不足」——这是给玩家的一句提醒，不是错误。

**配描述**：描述风格的注册地址必须**覆盖**地标地址（更粗或同址），方向与地标之间相反：
地标之间互相包含都算配，描述却只能「更粗罩住更细」。覆盖分层（同址 > 覆盖 > 未注册）的
完整用法见 [report_selection.md](report_selection.md)。

报告进行中，角色位置会不断更新为**最后到达的最详细地址**；新地标与这个位置的距离在范围内
才视为可达。

## 4. 副本门口的地址

副本方案可以声明「入口地址 + 最大距离」，判定口径与上面同源：两者必须同维度，距离区间的
**上界**不超过上限才能进，角色没有地址时不参与判定。字段与拒绝文案见
[dungeon/admission.md](dungeon/admission.md)。

这扇门和副本内章节的取景地址是两回事：入口决定「能不能进」，章节地址决定「进去后看到哪
一带」。

## 5. 给一个地标填地址（玩家可做）

打开地标编辑对话框，在「地址(可选)」里填。填法取决于它所属的风格有没有注册地址：

- **风格已注册地址**：只填风格地址之下的剩余级别，可以是一级 `East`，也可以多级
  `East-3`。例如风格注册在 `TH-GSK1`，地标在东部 3 号单元，就填 `East-3`。
- **风格未注册地址**：填完整地址（含维度与绝对规模），例如 `1e4_2e3_2e2@TH-GSK1-East-3`
  ——没有风格地址可依，这一条就是它的全部位置。若风格后来注册了地址，这个完整地址仍可
  使用，但必须与风格同维度、且落在风格地址之内，否则该地标不参与本次地址规划。
- **双击地址框**：弹出注册表里该风格地址下的全部**已申领子地址**（含各级精度与描述），
  点选即回填；后台会联网刷新，离线时用本地缓存。
  - 候选按地标尺寸过滤：最细单元边长小于地标尺寸的子地址会置灰标「不推荐」——塞不进去。
    想强行用就手动输入。
  - 改「尺寸(米)」会实时刷新推荐状态。

**留空的含义按地标类型分**：

- **独特地标**留空 → 继承所属风格注册的地址；
- **均值地标**不参与地址规则，到处可用；但如果你给它填了地址，它就与独特地标一样参与筛选。

> 给风格换注册地址会让原先组合出来的地标地址失效。对话框会给出警告，保存后请回头检查
> 各地标的「地址(可选)」字段。

## 6. 给整套风格注册地址（作者 / 维护者）

对象是文本管理器里的**地标风格**与**描述风格**，两者都有「📍地址」按钮：

1. 打开文本管理页，选中风格；
2. 选地址，两种方式任选：
   - **级联选择**：维度 → 一级 → 二级 → 三级，每级只列出注册表里已申领的选项；某级选
     「（不选此级，止于上一级）」表示地址到上一级为止；
   - **搜索**：在「序列化地址」输入框里按地址、描述或申领人过滤，点选结果后级联自动联动。
3. 点「确定」。程序会联网下载最新注册表并校验该地址确实已申领，否则拒绝；离线时提示
   「离线，无法注册」。
4. 想解除绑定：点「消除」再「确定」，这一步不需要联网。消除后该风格不再参与地址规则。

风格注册的通常是最上面若干级（维度必填），剩下的级别留给各地标自己补——这就是 §5 里
「只填剩余级别」的由来。

## 7. 申领一个新地址（注册表仓库）

申领与注册是两件事：**申领**只能在注册表仓库里手工做，程序内**不能**申领新地址；**注册**
是在程序内把风格 / 地标绑到已申领的地址上。

1. 打开在线注册表（见 §11），编辑其中的 `registry.json`；
2. 按树形结构（`worlds` → `regions` → `regions` …）追加节点，每个节点写上 `description`、
   `owner`、`claimed_at` 等申领信息（格式见 §10）；
3. 保存提交。之后在程序里点「刷新」就能看到新申领的地址。

> 申领信息会写进公开注册表：`owner` 等字段是给所有人看的署名。

## 8. 内部实现

- 配对、覆盖、距离、私有名约束由一次计算给出（`core/address_model.py::relate`，结果是
  `AddressRelation`：空间关系、距离区间、`chunk_ok`）。报告的「地标可达」与「描述配对」、
  副本准入都从这里取口径，不存在第二套算法。
- 两种失败不会被静默降级：角色位置解析不了给 `invalid_position`；地标地址存在但与风格
  组合不了给 `invalid_address`，该地标跳过并在规划结果里留诊断，不会变成「无地址、到处
  可用」。
- 注册表加载时会跳过不合法节点（规模个数错、id 不合法等），并在状态行提示，不会因为一条
  坏数据整表失败。

## 9. 拓展用法

- **用私有名划语境**：同一个世界里，不同作者可以用不同的私有名（`chunk`）各写各的分支，
  互不干扰；想让自己的地址在别人的语境下也成立，就申领一个**平行地址**——私有名只取路径上
  最先声明的那个，子地址覆写无效。
- **给独特地标写完整地址**：即使风格已注册，也接受完整地址（同维度、在风格地址之内即可），
  方便从别处复制一条地址直接粘进来。
- **旧扁平格式仍能读**：自己维护的注册表若还是 `version: 1` 的列表或映射形式，程序照样
  认，不必先迁移成树。
- **地图可以只申领到维度**：维度节点本身就是一条申领记录，允许注册「纯维度地址」（无规模），
  适合先占住一张地图、再慢慢细分。

## 10. 参数表

<details>
<summary>地址文本格式、组合规则与 registry.json 的完整写法（写地址 / 维护注册表时展开）</summary>

**地址格式**

```
<绝对规模>@ [<私有名或*>!]<维度>-<一级地域>-<二级地域>-<三级地域>
```

- **绝对规模**：以 `_` 分隔的 3 个数字，按一级 / 二级 / 三级给出该级单元的边长（米），
  如 `1e5_5e3_1e2` = 一级 100 km、二级 5 km、三级 100 m。包含地域段时必须给；纯维度地址
  可省。
- **约束段**（`@` 与 `!` 之间，可省）：完全没有 `@…!` 段 = 不与任何带约束的地址匹配；
  `@!` 或 `@*!` = 不指定私有名；`@abc!` = 要求私有名恰为 `abc`。
- **维度**：字母 / 数字 / 下划线，1～48 字符。
- **地域 id**：每级字母 / 数字 / 下划线，1～16 字符；最多三级（整个地址最多维度 + 3 段）。

示例：`1e5_5e3_1e2@abc!ea1-1-2` = 一级 100 km、二级 5 km、三级 100 m，私有名 `abc`，
维度 `ea1`，一级地域 `1`，二级地域 `2`。

**组合规则**（风格地址 + 地标地址 → 完整地址）

- 规模：「更细一方胜出」——地标带绝对规模时覆写风格的规模；
- 私有名：取先声明的一方（风格在前，地标覆写无效）；双方都声明具体私有名且不同时，
  组合失败；
- 地域 id：风格前缀 + 地标多余的后缀（公共前缀去重）；
- 维度不同、地标地址不在风格地址之内（分支分叉）、层级超过三级，都会报错，该地标不参与
  本次地址规划并留诊断。

**registry.json（树形式，推荐）**

```json
{
  "version": 2,
  "worlds": {
    "TH": {
      "description": "东方Project", "owner": "紫", "claimed_at": "2026-09-05",
      "regions": {
        "GSK1": {
          "scale": ["1e4", "2e3", "5e2"],
          "description": "幻想乡腹地",
          "regions": {
            "East": {
              "description": "幻想乡东部区域",
              "regions": {
                "hrjj": {"scale": ["3e2"], "description": "博丽神社"}
              }
            }
          }
        }
      }
    }
  }
}
```

- 节点字段：`description` / `owner` / `claimed_at` 是申领信息；`scale` 是该级申领的规模
  数组；`chunk` 是可选私有名；`regions` 是下一级地域。
- **申领规模规则**：一级地域**必须**带 3 个规模；二级地域可选带 2 个（覆写该分支的二级 /
  三级边长）；三级地域可选带 1 个（覆写三级边长）；未覆写的级别沿路径继承上一级。所以同一
  分支内的规模一致性由树结构保证，不同分支允许不同规模。
- **私有名不参与覆写**：只取路径上最先声明的值。

**旧扁平格式（兼容）**

```json
{"version": 1,
 "addresses": [{"address": "1e4_2e3_2e2@TH-GSK1-East-hrjj", "description": "博丽神社",
                "owner": "紫", "claimed_at": "2026-09-05"}]}
```

映射式：`{"1e4_2e3_2e2@TH-GSK1-East-hrjj": "博丽神社"}`。

**命名规范（推荐）**：维度用大写字母缩写；一级地域用大写字母缩写 + 数字；二级地域用首字母
大写的完整词；三级地域用小写字母缩写与数字。同一地域下的直接子地域不应重名。

## 11. 官方资源

程序不自带地图数据：能选的地址全部来自在线注册表，首次使用时下载并缓存，之后离线也能查看
与选择本地已缓存的地址。

- 在线注册表：<https://gist.github.com/j71408028-netizen/da0b6204e57a411462f2d72e3e0f1997>
- 注册表里的地址按维度分成若干世界；每个世界下是各地域分支，申领信息随地址一起公开。

## 12. 作者须知

- **注册必须联网**：每次点「确定」都会重新拉取注册表并校验申领状态，只能注册其中已申领的
  地址；离线时只能查询缓存或清除绑定。
- **一个风格换地址会波及地标**：旧组合出来的地标地址失效，保存后逐个检查。
- **私有名不可覆写**：子地址写别的私有名不会生效；需要换语境就申领平行地址。
- **坏节点不阻断整表**：不合法节点被跳过并提示，但也就意味着那条地址不存在——申领后请在
  程序里刷新确认能看到。
- **地标尺寸与地址精度要对得上**：最细单元比地标还小的地址属于「不推荐」，界面只置灰不
  禁止，最终仍由你判断。
