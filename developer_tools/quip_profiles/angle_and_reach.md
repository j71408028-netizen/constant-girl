# 描述语料的场景卡：视角与表现手法怎么配

> **这一篇回答什么问题**：给一个题材写 `quip_profiles/*.json` 时，「视角」和「表现手法」
> 这两栏到底在管什么、写成什么样才算对。读者：写描述风格（quip 语料）的作者。
>
> 字段形态、`touch` / `landforms` / `parts` 的写法、`doctor` 的判据都在
> [本目录 README](README.md)；
> 这一篇只讲**这两栏的设计口径**，不重复字段表。
> 描述在报告里落在哪一行，见 [报告生成](../../docs/designs/report_selection.md)。

## §1 先把 quip 的位置搞清楚

一条 quip 在报告里是**一行独立散文**，位置固定在：

```
📏 膝盖 128m
└─ 相当于一个街区
QUIP_LINE:"……"
    ────────────────────
    2026-11-14
    本报告总计伤亡：……
```

（`services/exploration/report_text.py` 里 `📏 部位 尺寸` → 对比行 → `QUIP_LINE` 的次序。）

这决定了它同时受两种要求拉扯：

| 拉力 | 来源 | 表现 |
|---|---|---|
| 要**配得上上面那行数字** | 报告结构 | 这一下落在哪个部位、碰到了什么，得能从句子里认出来 |
| 要**读起来不像数据** | 它是散文 | 语感、节奏、口吻要活 |

只满足前者，语料像另一份报告；只满足后者，语料脱离巨大化设定，跟上面的尺寸对不上。
视角和表现手法这两栏，就是用来同时压住这两头的——**它们是杠杆，不是装饰**。

由此得到两条在每一份 profile 里都该抄进去的硬规则（`rules` 里必须有）：

```json
"这一条是报告里的一行，上下都是数字和对比；抽出来单看也要能对上它那一栏：给出的着重部位、碰到了什么、变成什么样。",
"报告不是她的日记：私人化的、只对一个人说的口吻不能原样搬上来，要换成报告能承载的说法。"
```

### §1.1 「在报告里」不等于「她必须出现在句子里」

这两种约束很容易写混，写混了会把整份语料压成一种姿势。区别在于**部位**这一栏：

- 介入度 2~4 的格，着重部位是**身体的某一部分**（膝盖、手、指尖……）。这些格里，
  她本人就在场上做那件事，句子当然要写她。
- 介入度 1 的格，「她只是在场」，着重部位本身就是`某个角落`、`影子`、`轮廓`——
  **这一档她完全可以不出现在句子里**，写的是她在那儿留下的痕迹、周围因此变了什么样。
  这是定义，不是漏洞：`parts` 里给 1 级配这三个词，就是为了这一档能这么写。

所以真正要守的不是「她必须字面出现」，而是：

1. **写到的接触要落在给出的着眼部位上**（给的部位是哪一级，就写哪一级的事）；
2. **口吻要能进报告**——下面 §2 的全部内容都是在说这一条。

反过来，`她必须在场，字面出现，不能只以影子、影响或“某种存在”的形式被提到` 这句话
**不要写进 `rules`**：它会让介入度 1 的格无话可写，写手只能硬塞一个她进来，
产出的东西既不像 1 级也不像 2 级。

## §2 视角：换的是**叙述口吻**，不是观察者

这是最容易写错的一栏，而且错了之后整份语料都会跑偏。

### §2.1 病灶长什么样

早期 profile 的视角是一串**具体的人**：抄表的、收摊的、蹲下去翻拣的、不敢出声的目击者。
它们读起来很有画面，但进题面之后会触发一个连锁反应：

1. 写手看到「收摊的店主老周，手里还攥着挂钩」，先补的是**这个人的处境**；
2. 补完人设，句子的主语就变成了「他」；
3. 于是产出「路口几个人没商量完绕路，上面蹭过一阵闷响」——她的部位只剩「上面」，
   接触只剩「一阵响」。

把这一行贴回报告，`📏 膝盖 128m` 下面接一句只有「上面」的话，尺寸就没有着落了。

**换一份题材不会自愈**：内置样板 `template.json` 的 24 个视角里有 6 个权重 3 的
「带职业 + 手上动作」的人物，全部落在同一个坑里。所以这条不是某一份 profile 的疏漏，
是配视角时的通用陷阱。

### §2.2 正确的口径

视角回答的是「**这一下由谁来叙述**」，而不是「由谁来看」。同一件事、同一个接触点，
换的只是话从哪个口吻里出来：

| 口吻 | 一句话说明该怎么落笔 |
|---|---|
| 被写进报告的现在时 | 先写她这一下落在哪、碰到了什么，再顺口带一句周围的样子 |
| 她自己的那一句 | 她的吐槽或自问紧挨着描写出现，不是独立的一段心理活动 |
| 旁人在同一刻看见的那一下 | 他从某个位置看见了她的局部和它碰着的地方，**不交代他自己在忙什么** |
| 被写成制度口吻的一笔 | 通告、监测、归类，用公事腔记事 |
| 事后才补上的一句 | 事后有人补记或争论这一下算怎么回事，说的是这一下，不是他自己 |
| 按她自己的尺度写的 | 从她那边看：这东西多小、多碍事、值不值得伸手 |

判断写法对不对，可以用一句话自检：**这个标签能不能被写成「某个职业的人此刻在干什么」？**
如果能，它就是观察者，要改。改成「谁在说这件事」就对了。

### §2.3 三个配套要求

1. **`note` 是这一栏的主体，不是标签的注解。** `doctor` 只查「缺 `note` 会报」，
   但真正决定产出的就是这句话。写 `note` 时要说清**落到哪**（哪一下、哪一处），
   而不只是「用某某口吻」。
2. **不能带候选词表（`cues`）。** 词表进题面，写手会当成必写清单，整批文体塌成一种。
   `doctor` 会报「还带着词表：词表进题面就会变成必写清单」。
3. **权重只区分口吻好不好写，不分人物与制度。** 好写的口吻给 3，需要技巧的给 2。
   别给某一条 4——实测下来高权重口吻会挤掉别的口吻的配额。

### §2.4 权重怎么定、怎么验

抽样是确定性的哈希取模（`Profile.pick_angle`），不是均匀轮转：

```python
cell_index = rank[band] * 16 + (i-1)*4 + (d-1)
angle = pick_angle(cell_index + k*7 + seed*3)
```

所以**不同格、不同条、不同 seed 的分布会偏斜**。定完权重要按「全 70 格 × k × seed」
统计一遍，别只看一格的 6 次抽样。以 8 个视角、权重 4/3/3/3/3/3/2/2 为例，实测：

| 口吻 | 权重 | 实测占比 |
|---|---|---|
| 被写进报告的现在时 | 4 | 17.1% |
| 旁人在同一刻看见的那一下 | 4 | 17.0% |
| 其余三个 3 分口吻 | 3 | 12.2% ~ 12.5% |
| 两个 2 分口吻 | 2 | 8.2% / 8.3% |

最差的一组（`giantess_mythic`，权重 3/3/3/3/2/2/2/2）是 15.1% : 9.9%——更平，
但八个口吻同样都抽得到。**验收标准是「每条都抽得到」，不是「越平均越好」。**

### §2.5 私人口吻可以进来，但不能原样搬上来

视角池里留一条「她自己」是有用的——全是旁人口吻的池子，语感会整体偏成「别人在记录她」。
但这里有个分界，越过去整篇就不成立了：

| | 可以 | 不可以 |
|---|---|---|
| 谁的视角 | 她（巨大娘本人） | 任何一个旁人 |
| 什么内容 | 她此刻的注意力、判断、心念 | 这个人的日记、随笔、自我剖白 |
| 什么形式 | 一句话，紧挨着正在发生的那一下 | 独立成段的第一人称独白 |

判断标准很简单：**这条东西如果原样归到某个地方报上去，读得通吗？**

- 读得通——那是报告能承载的说法，可以留；
- 读不通，它只对「写它的那个人自己」有意义——那是日记或随笔，不能原样搬上来。

举例：`她低声问自己，是这儿吧？` 是她的口吻，但它是**关于这一下**的一句，
挂在报告里成立。而「今天又把路踩坏了，有点烦，妈打电话问我最近怎么样」
这种就只对写字的人自己成立，不能进语料——哪怕主语是她。

**只有她本人**能带这种近距离口吻（她是报告的对象，近写是合理的）；旁人的内心活动、
私人感受一旦原样出现，就变成了一篇不属于这份报告的东西。所以：

- 视角池里至少留一条「她自己」，且 `note` 里写清「话是关于这一下的，不是一段自我剖白」；
- 其他口吻即便以「他」为主语，也只能写**他说出来的、写下来的、记下来的**，
  不能写他在想什么、他回家以后怎么样。

注意这两条都是**跨条约束**，只能靠 `rules` 压着，`--batch 1` 逐条写时没有分母可依。
真要强制，得给它们一个代码可读的信号——属于工具改动，不在 profile 里。

## §3 表现手法：管「怎么写」，不管「写到哪」

### §3.1 一条手法该长什么样

`craft.reach` 是一张平铺表，每项 `[短名, 说明]`。短名**不进正文**，只在题面里
告诉写手「用哪种写法」；说明一句话点出笔法。

合格的手法说明有三个特征：

- **只定笔法**：`「同一下里，她的感受与旁人的判断各写一半，两边错开。」`
- **不定落点**：不写「写在最后」「结尾再收」，也不写「接触面所及什么都不剩」这种成稿。
- **不带实体与数量**：说明里出现具体物件，写手会照抄，这一格就只剩一种写法。

`doctor` 对说明里的「最后 / 结尾 / 之后」会报（`quip_draft_bench.py:765`）。
这条拦截和「先拖后拖」这类**需要时序**的手法天然冲突——目前靠换措辞绕过
（「之后再拖一段」→「然后再拖一段」）。

### §3.2 手法不承担破坏程度

手法挂在副轴上，但和动作类型**互不映射**：副轴 2「轻触」不规定必须用哪个手法，
副轴 3「施力」也不要求写成特写。所以手法跨级复用是设计，不是省事——
破坏边界由动作类型定（`ACTION_HINTS`），手法只管笔法。

这条也解释了为什么 `craft.reach` 是**一张表**而不是四级各抄一遍。

### §3.3 8 条和 12 条的区别

同格 3 条按 `k * 7 % 池长` 走。池长 8 时，三条落在序号 0 / 7 / 2，覆盖到池子的三段；
池长 12 时落在 0 / 7 / 2，同理。**池长和 7 互素**是关键——池长取 7 的倍数会让
同一格的三条反复落在同一个位置上。

数量按需要定：手法池越大，一格内越不容易重复，但每条手法的说明就要写得更克制
（12 条里出现三条都在写「景包裹事件」，整份语料就会被带成游记）。经验值是 **8~12 条**。

### §3.4 手法之间要分工，不要同义

写完一批手法名之后，把它们按「管什么」分个组，别让三四个手法都在管同一件事：

```
管节奏  慢镜 / 先拖后拖 / 省略
管落点  特写 / 远观再推近 / 时间跨度
管口吻  称谓 / 追认意义 / 转述或错认
管材料  对比 / 比喻 / 数字错位 / 单一感官
```

一个维度上超过三条，就要考虑是不是该合并或替换。**这一条是修「主基调被抢」最有效的方法**：
某一组手法全在写景，产出的语料就会变成游记，无论 `rules` 里怎么声明都没用——
写手照的是手法，不是规则。

## §4 两栏的联动：先定基调，再配手法

视角和手法不能分别挑，否则会出现「口吻是纪实的，手法全是抒情」这种撕裂。做的时候按顺序：

1. **先定这一份语料的消费位置与基调。** 它要配的上面的尺寸（§1），基调是什么
   （淡漠、使命感、紧迫……）。基调不进手法表，进 `rules`。
2. **再定手法，让手法服务于基调。** 基调是「慢而飘忽、每个动作都有意义」时，
   要有管节奏的手法（先拖后拖）和管口吻的手法（追认意义）；只有慢镜和写景是不够的。
3. **最后配视角，保证口吻能承载这个基调。** 基调是使命感时，视角要有「她正在做这件事」
   和「她自己在确认」，不能全是制度与档案。
4. **跑一遍统计与 doctor，再拿两三格实测。** 每格 6 条、固定 seed、`temperature 0.9`，
   对照语感验收。

检查手法是否抢了基调，看产出的**前三条**就够了：如果前三条都在交代天气、街景、
地名来历，说明有手法在写景上占了主导权。

## §5 常见失效与对应的改法

| 现象 | 病灶 | 改法 |
|---|---|---|
| 产出像另一档的事，部位只剩「上面」 | 视角写成了观察者 | 改成叙述口吻（§2.2） |
| 每条都在补一个路人的人设 | 视角带职业与手上动作 | 同上；`note` 里明写「不交代他自己在忙什么」 |
| 语料读起来像某人的日记 / 随笔 | 把私人化口吻原样搬上来了 | 换成报告能承载的说法；只有她本人可近写（§2.5） |
| 全篇听不见她，像别人的观察笔记 | 视角池全是旁人口吻 | 补一条「她自己」的口吻，`note` 限定在「关于这一下」（§2.5） |
| 文体整批塌成一种 | 视角带了 `cues` 词表 | 删掉词表，只用 `note` |
| 语料变成游记 | 写景类手法占了三条以上 | 按 §3.4 重新分工，把写景压到一条 |
| 后半句都在收束、像总结 | 手法说明里写了落点 | 删掉句内位置词，只留笔法（§3.1） |
| 同一格三条读起来一样 | 手法池长是 7 的倍数 | 池长与 7 保持互素（§3.3） |
| 某个口吻占满配额 | 权重给了 4 | 降到 3，按 §2.4 重新统计 |

## §6 现状

三份本机 profile 的体检（`doctor` 全部 `problems 0`）：

| profile | 视角 | 手法 | 字数 | 基调 |
|---|---|---|---|---|
| `giantess.json` | 24（含 6 个具体人物） | 8 条，四级共用 | 85~150 | 记录 / 观测，语感偏生硬 |
| `giantess_casual.json` | 8 个叙述口吻 | 12 条 | 60~120 | 淡漠、惊奇、略带无聊 |
| `giantess_mythic.json` | 8 个叙述口吻 | 12 条 | 60~120 | 苏醒后的使命感，慢而飘忽 |

`giantess_casual` 与 `giantess_mythic` 共用 `bands` / `landforms` / `vague` / `banned` /
`patterns` / `craft.parts` / `craft.action_modes`——判档依据必须共享，两份语料才能互换。
换题材时的完整步骤见[本目录 README](README.md)「怎么换一个题材」。
