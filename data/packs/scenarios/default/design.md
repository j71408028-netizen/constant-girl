# 回稳会志 · 分线设计说明

> 配套文件：`config.json`（方案本体）、`texts/ch0_xing.txt`（第一章固定文本）。
> 这份文件只讲结构，不重复正文；改方案前先看第 4 节的调参旋钮。

## 1. 为什么不再密集插句

上一版（`huiwen_huizhi_ai`，自建实验版）用「节内计数 1/2/3/4/5/7…」把一整章的拍点
全部钉成插入段落，等于每两段就被插入段接管一次。结果是 AI 只负责衔接，真正推进的
全是写死的句子——读起来是分镜表，不是她在一个陌生的地方摸索。

这一版把插入段压到**每章一拍**：一章里最多出现两条（互为补集，实际只播一条），
其余全部交给 AI。写死的句子只用在三处：

- 第一章：整章固定文本（`texts/ch0_xing.txt`）。
- 状态分线的岔口：同一位置必须给出两种不同的事实（压进地里 / 只塌一角）。
- 选项的应答：玩家选了，就得有人回话。

固定文本章节**不能**放插入段（`script.md` §2.5：两套推进模型冲突，运行时会跳过、
校验器会报警），所以第一章的拍点直接写在脚本里，不进触发器。

## 2. 章节图

```
1-1 醒（固定文本）
 └─ overflow → 1-2 起（AI）
      └─ goto(节内≥9) → 1-3 走（AI）
           └─ goto(节内≥9) → 1-4 猜（AI，夜里两道坡之间）
                ├─ goto(节内≥9 且 破坏性 < 2.5)  → 2-1 坳口·还在运转（结局）
                └─ goto(节内≥9 且 破坏性 ≥ 2.5) → 2-2 坳口·围起来了（结局）
```

两章结局都停在她到坳口：**能不能下去、下面的人要不要她下去，一概不写**。这是这一版
的边界，也是后面续写的接缝。

## 3. 分线怎么落地

### 3.1 互补对：同一拍点，两条触发器

```
起·压进地里   节内计数≥3 且 破坏性≥2.0
起·只塌一角   节内计数≥3 且 破坏性<2.0
```

同一拍点的两条触发器条件互为补集，**任何状态下恰好有一条成立**。这比「只写一条高门槛
触发器、不满足就什么也不发生」稳：不会出现「这一拍静默跳过、节奏塌一格」，也不会因为
角色性格标定不同而整条线永远走不到。

### 3.2 门槛阶梯

介入度 / 破坏性的坐标域是 0.5–4.5，副本起始值是 2.0 / 1.5。门槛跟着剧情往后抬：

| 章节 | 破坏性 | 介入度 |
|---|---|---|
| 1-2 起 | 2.0 | 2.1 |
| 1-3 走 | 2.3 | 2.3 |
| 1-4 猜 / 结局分章 | 2.5 | 2.5 |

早段门槛低（她刚站起来，任何一点挣扎都算），末段回到中轴（这一路到底压坏了多少，
在这里结账）。

### 3.3 终局为什么只按破坏性分章，介入度放在章内

AI 每段只给一路 `direction`（-1 受挫 / 0 中性 / +1 顺利，见 `prompts.py`），**介入度与破坏性
吃的是同一个方向**，天然同涨同落。若按 2×2 分四章，实际只会走对角线两条，
另外两条写了也播不到。

所以：

- **破坏性 → 章级分线**：坳里还在正常运转，还是已经围起桩绳、人全退到岩壁后。
  这是「她这一路压坏了多少」最直接的外部后果，也正好对上回稳会「按风险分级接待」
  的办事方式。
- **介入度 → 章内分叉**：同一座坳口，她伸手与不伸手，接待她的人上来与不上来。
  同样是插入段互补对，只是作用域落在结局章节里（结局章节不禁 `insert`，
  只禁 `goto` / `option`）。

### 3.4 选项也会改状态

1-4 的两个选项各挂一条 `effect`（`duration: 3`）：

| 选项 | 效果 |
|---|---|
| 问她那上面是什么 | 介入度 sensitivity `objective +0.8`，3 步 |
| 什么都不问 | 介入度 sensitivity `objective -0.8`，3 步 |

`effect` 的敏感数组是**整维替换**，所以两条都把 `数字` 那条一起写回去，`objective`
一律 `0.0`：那个数是累计击杀数，只会涨，不该被剧情推着往下掉。
这样玩家「问不问」这一步，会实打实影响最后走哪一条介入度插入。

### 3.5 饥饿游戏：配置层与叙述层分开

`cast` 里那位 `student`（饥饿游戏）只有 `background` 一处能承载人设，而它有一个硬约束：
**引擎每段给 AI 的「人物简报」只取 `background` 的第一句**（`characters.py::_digest`，
≤60 字，分号也算句末）。写在第二句以后的内容只在首次出场出现一次，之后就滑出上下文。

所以第一句必须自包含「她现在是什么人、在做什么」。这一版的第一句是「不良少女醒者，
比你高出一大截，拿活人当玩具……」，简报里每段都会带上它；终端、数字、回稳会那一段
来历放在后面，供首次出场时铺开。

`background` 是给 AI 的真相，不是主角的认知。主角那一层写在 1-4 的 `note` 里：她第一眼
只看到一个穿校服、比自己早来、说话轻快的同龄巨娘；真相只从三处漏出来——被压得过分平
的空地、她看远处不肯挪开的眼神、她说到那个数时的语气。她本人不解释、不自夸，问到了
只说一句「这是我杀掉的人数」，说完就反问「你不是也有吗」。

数字是累计击杀数。回稳会发终端，本意是让巨娘盯着它学着收着点；她把它读成了比分，
才给自己这玩法起了「饥饿游戏」这个名字。

## 5. 待验证

- 门槛是按坐标中轴 + 起始值推的，没有实机跑过。第一次试玩后重点看：1-2 第 3 段时
  破坏性落在 2.0 的哪一侧；若三次试玩都同侧，按第 4 节平移门槛。
- 2-1 / 2-2 只有 5 段上限，插入段占 1 段。若觉得收得太急，先加 `max_paragraphs`，
  别急着加插入。
- `texts/ch1_qi.txt`、`texts/ch2_zou.txt` 是上一版留下的整章散文，已不被引用，
  留作改写参考；要复用请拆成插入段，不要整章接回固定文本。

## 6. 地址：本副本不注册

按现在的地址系统，这一版**不需要**为回稳会申领地址：

- 方案 `entry_address` 留空 = 不做地址准入，角色有地址也照样能进；
- 六章 `address` 全空 = 虚构章节，提示词不写地点行，也就没有东西可漏；
- 结局 `exit_address` 全空 = 结束后角色位置不变；
- 章节 `scene_landmarks` 用的是**内联尺寸**（坳壁 / 灯杆 / 坳口），不查地址、不走私有名，
  所以连 `common_private_name` 都不用填。

将来真要在主世界里给回稳会落一个点（比如做成可进入的地标），按注册表的树形格式申领：

```json
{
  "version": 2,
  "worlds": {
    "HW": {
      "description": "回稳会所在的巨娘世界",
      "owner": "填入申领人",
      "claimed_at": "2026-11-20",
      "regions": {
        "HW1": {
          "scale": ["1e4", "1e3", "1e2"],
          "description": "回稳会临时管教区",
          "regions": {
            "Basin": {
              "scale": ["5e3", "8e2"],
              "description": "盆地群",
              "regions": {
                "hw1": {
                  "scale": ["6e2"],
                  "description": "主角抵达的那座坳子"
                }
              }
            }
          }
        }
      }
    }
  }
}
```

规模规则：一级地域**必须** 3 个规模，二级可选 2 个、三级可选 1 个（不写就沿路径继承）。
申领在注册表仓库里手工改，程序内只能注册已申领的地址；申领后把完整地址
（形如 `1e4_1e3_1e2@HW-HW1-Basin-hw1`）填进章节 `address` 或方案 `entry_address` 即可。


## 7. 章节背景图提示词

用途：填入章节 `background.image_path` 的图。**四张**——1-1 与 1-2 共用 A
（她躺着 / 她坐起来），2-1 与 2-2 共用 D 的同一机位（坳底有没有人），1-3 是 B，
1-4 是 C。

画幅建议 16:9、1920×1080 以上；每张按「构图（人看的）→ 提示词（给模型的）」
两段写，提示词是可以直接粘进文生图工具的成稿。

三条贯穿全篇的硬约束（AI 不认识这套世界观，不写死就会乱画像别的作品）：

- **巨神种不是怪物**：她就是一个穿校服、十几岁模样的少女，只是大得离谱。
  不要触手、角、鳞片、发光的眼睛、机甲、胶衣。
- **尺度靠对照物，不靠特效**：房子、车、坑壁岩层、云、杆子——用这些给出比例；
  不要用镜头光斑、能量场、崩坏特效来表达「巨大」。
- **低饱和、干、灰**：这一版是煤与尘土的颜色（1-1 章节色 #8C7A5B），
  夜戏也只有星和月光，没有霓虹、没有品红与青色的对比色。

负面提示词（四张通用）：

```
怪物化、触手、角、鳞片、发光眼睛、机甲、胶衣、紧身衣、暴露衣物、胸部特写
镜头光斑、能量场、爆炸特效、末日红光、霓虹、高饱和、HDR、赛博朋克
人物正脸特写、仰拍腿部、多个巨大女性、文字、水印、logo、签名
```

### 7.5 与配置的接法

图存在方案目录的 `images/` 下（`a.jpg`~`d.jpg`），对应关系：

| 章 | 图 | 说明 |
|---|---|---|
| 1-1 / 1-2 | `images/a.jpg` | 同一机位：她仰躺，镇子与矿坑在脚边 |
| 1-3 | `images/b.jpg` | 跨省行走，远处坡上那个更矮的剪影 |
| 1-4 | `images/c.jpg` | 夜，两道坡之间，手里那块亮着的东西 |
| 2-1 / 2-2 | `images/d.jpg` | 坳口俯视；目前只有搬空版，两章共用 |

```json
"background": {"image_path": "images/a.jpg", "smooth_transition": true, "filter_effect": ""}
```

`filter_effect` 一律留空：滤镜清单只有模糊 / 锐化 / 浮雕这一组，**没有调色**，
所以色彩只能在上游的图里定，不能靠章节滤镜补救（留空表示本章不加滤镜，
切章节时也不会把上一章的滤镜带过来）。

### 7.6 本批图的实测与处理

改图前对四张原图（1672×941 PNG，共 9.3 MB）测过亮度分布：

| 图 | 亮度均值 | 对比度（标准差） | 判断 |
|---|---|---|---|
| a | 88.9 | 30.1 | 正常 |
| b | 82.4 | 29.6 | 正常 |
| c | **31.0** | **9.6** | 过暗、被蓝偏色占着，正文压在上面会糊 |
| d | 62.9 | 28.3 | 正常 |

四张都没有死黑或死白（0 与 255 的像素占比为 0），所以不需要动降噪或补光，
只处理 c 与统一体积：

- **c 的调色**：先让通道向亮度靠拢重新饱和 0.5（消掉蓝偏色），再整体乘 2.2
  把挤在暗部的结构拉出来。结果均值 31.0 → 67.9、对比度 9.6 → 20.8，仍是夜景，
  但进了 a/b/d 的同一区间。**纯 gamma 提亮不行**：均值能到 78，对比度却只有 13，
  画面发白发雾。
- **统一转 JPEG q94 / 全采样**：PNG 存写实照片是浪费，而 chroma 抽样会把
  a/b/d 里细密的房屋边缘弄脏。四张 9.3 MB → 1.9 MB（省 79%），
  与原始 PNG 的亮度 PSNR 在 43.5~49 dB，属视觉无损。
- 方案目录里只保留转码后的 JPEG；要重调色，按上面两步的参数从原图重做即可
  （去饱和 0.5、增益 2.2、暖偏 1.04）。

只会成为放大源。
