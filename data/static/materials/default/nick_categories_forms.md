## 尾饰：什么时候该补一个符号

挂在句末的那一个字符，**不是统一的装饰**。它们的正业是**把一个没收尾的句子收住**：
语气还没说完、句子故意停在半截、或者后面本来还有话。
所以判断很简单——**这条要是不是「话没说完」的样子？** 是，尾饰就有活干；不是，它只是包装。

**能用什么由「符号池」定，不由印象定。** 池子按码位范围判（见「符号池：按码位范围，不按清单」），
不限于 `°`、`~`、`…` 这几个：装饰符号（`☆ ✧ ✦ ❀`，以及 `❤ ☀ ☂` 这类黑白 emoji）、**数字**（`404`、`7`、`24`）、
**罗马与希腊字母**（`Ⅻ`、`Σ`、`Ω`、`ξ`、`π`），以及中文标点（`。`、`？`、`！`、`…`，形态上算中文），
乃至一句「没收尾」的自造短语，都可以当尾饰。判据只有一个：**它在句末扮演的是「还没说完」，
而不是「这条的名字」。** 换成另一种说法——**尾饰不承载语义，它只负责把语气悬住**；
一旦它自己也要被读成内容（一个物件、一个编号、一个身份），它就不是尾饰，而是这条的正文。

以下这些确实是正文，不要当尾饰删：`104路夜班车`、`异常收容物_173`、`π的无限不循环`、
`深渊观测者ξ`——符号在中间或者本身就是那个东西的名字，删掉条目就空。

三种最该用尾饰的情形：

| 情形 | 不带尾饰 | 带尾饰 |
|-|-|-|
| 省略形态（省掉了主语、宾语或后半句） | `断桥借伞人。` 不像话 / `U` 太硬 | `U。`、`不聊了。`、`{given}正在输入中…` |
| 「了」或短动词收尾，句子已经讲完但语气没落地 | `算了` 太干、`好酷儿` 像在陈述 | `算了。`、`好酷儿~`、`不聊了~` |
| 氛围型短句，补实物就散 | 硬改成 `夜行姑获鸟叼着伞` | `春眠不觉欧~`、`她先开口~`、`草莓奶油塌了…` |

**双关的尾饰不按「话没说完」判。** `熵增∞` 的 `∞` 既是装饰符号又是数学符号，
「熵增到无穷」和「给熵增挂了个无穷」两个读法同时成立——这类条目读的是**两个字面同时在场**
（与 `Qing心灵语` 同一条判据），删符号就等于拆掉其中一层。下面「已用符号做结构的条目」都归此类。

**尾饰到位就不要重写。** 上面第三行是这一节最实际的用处：`姑获鸟°夜行` 的病在 `°`
（它在这里是插在词中间的分隔），不在句子；四字主谓本来就把这件事说完了，补一个实物反而变钝。
把 `°` 换成句末的 `~`，一条就立住了。同类还有 `春眠不觉欧`——谐音梗半掉不掉的状态正是它
的全部内容，落成 `抽卡不出货才叫欧皇` 就丢了。

两类不该用：

- **主语与谓语都齐全的句子**：`{given}今天不营业`、`护照盖章将满`、`书房钥匙归贝壳`——
  意思说完了，加尾饰是往一句完整的话后面贴贴纸。
- **已经用括号收了可省略成分的条目**：`{sur}可（还在长）`、`阿楠（云上见）` 的括号就是收尾，
  再挂符号是两重收尾。

**符号按位置判例放，不按次数躲。** 去否定的时候用尾饰兜底，八条否定句可能全挂同一个 `~`——
这不是违规：符号各有自己的位置判例（见下「符号的位置判例」），位置对了，同一个符号用几次都对。
改完一批要查的不是「这个符号出现了几次」，而是「它挂的位置对不对」：尾注只在话没说完的句子末尾，
中段强调在词与词之间，对偶在并列的两半之间。位置错了，换一枚符号也救不回来。

同一条判据顺带说明：符号不必挑最常用的那个。`只在你面前变小…`（省略号：话咽下去）、
`秋千晃到一半〰`（波浪形符号本身就是晃动）、`春还没站稳_`（下划线：名字被截断）——
符号和句子之间能对上一件事的时候，它才不是一个可以随便替换的贴纸。

**取用时别凭手感，抽一下。** 规则放开之后真正卡人的不是「能不能用」，是「下一个用哪个」——
凭手感永远先想到 `~`。改句尾之前跑 `.temp/nick_repolish/tail_pick.py`，它会按句意挑一档、
避开表里已经用滥的符号，一次给几个候选：

```
python tail_pick.py --msg "春还没站稳"          # 自动判断语感，给 8 个候选
python tail_pick.py --kind 截断 --exclude "~"   # 指定档位、额外排除
python tail_pick.py --report                   # 只看当前占用，判断该不该再补
```

**数字与字母可以放心用**：`xxx2019`、`xx_07`、`xxΣ` 这类尾巴是中文昵称里最普通的防重方式，
读者不会把它读成「编号」，只会读成「这个名字被人占过了」。所以它们和 `~`、`★` 一样是正当尾饰。
唯一要留意的不是「能不能用」，而是**别让它变成一句谎话**——`女团舞十级学者` 的 `十级` 是刻度
（见「不用阿拉伯数字」），`她2019` 的 `2019` 才是附加。判据仍然是位置：挂在句末当尾巴，就是尾饰；
写在句中当量词，就是刻度。

四档分别对应四种「没说完」：**省略**（话咽下去）、**轻跳**（还在动）、**装饰**（只把语气挂住）、
**截断**（名字断在这里）；另有两档防重附加——**数字**（`07`、`2019`、`404`、`Ⅻ`）与
**字母**（`α`、`Ω`、`K`、`oL`）。数字和字母本来就是中文昵称最常见的防重办法，不必回避，
只是它们不像符号那样「用满即停」：`2019` 用得多，不代表 `404` 不能用。

同形异码本来就是一个东西——`～` 已在「符号池」里折成 `~`，两个码位不是两枚符号，换码位躲不过占用计数；
但**重复本身不再是停用理由**，位置判例对了就能继续用。当前表里 `~`、`°` 已多，那是因为它们过去被当默认尾饰乱挂，
不是因为数到了某个阈值——先按位置判例复核，位置对的留，位置不对的换。

**不看「是哪一枚」，只看「在哪个位置」。** `△` 与 `♤` 之间没有高下，一枚符号在符合判例的位置上
反复出现也不违规（见「符号的位置判例」）。哪几枚可用由「符号池」的码位规则定，不在这一节报菜名。

**中文的强语义标点可以用**——`，`、`、`、`？`、`！`、`（`、`）`、`“`、`”` 等都有自己的判据
（见「尾饰」「括号只做一件事」），但它们在形态上**属于中文，不属于符号**：一条只有汉字和这类标点的
条目仍算纯中文，不能拿它们去凑混杂式的符号名额。

**禁用项在「符号池」一次说全**（默认彩色的 emoji、变体与组合符、路径字符），这里不重复列。
那几条不是「这一批先别用」，是**改到就用不了**：彩色 emoji 会被平台涂成一片色块，
路径字符过不了保存与跨平台。

**括号是唯一被限死用法的符号。** 它只装可省略的内容（见「括号只做一件事」），
所以既不当尾饰，也不拿来分隔。其余符号不限制用哪一枚，只看位置判例；默认彩色的 emoji 与路径字符
则整组不进池子（见「符号池」）。

其余约束：

- **尾饰让位给署名**：条目已经以 `_{given}` / `_{sur}` / 固定名结尾的（`深夜回收站_小雾`），
  或者句末正好是 `{given}` 被占位符填满的，不加尾饰。这一条落在**句末位置**，不落在字面末尾。
- **一个符号，不与引擎冲突**：`_` 是署名分隔，`{` `}` 是占位符；同一个符号不要连用（`~~`、`！。`）。
- **一个收尾就够**：既有「了」又有尾饰，就是两个收尾，取其一。
- 存量比配额重要：整列读下来是不是同一个人在说话，比每条挂不挂符号更要紧。

### 符号的位置判例

一般条目里符号放哪，按三种位置判例走，**不必担心重复**——同一个符号在符合判例的位置上出现几次都行；
只有自造类（造词与符号、自造意象短语等靠字形取胜的列）不受位置约束，可以自由放。

| 位置 | 判据 | 例 |
|-|-|-|
| 中段强调 | 符号插在词与词之间，把后一段顶起来。**成不成对、用几个都可以**：只放一枚（`班图南迁-草原风`）、成对（`✦偷月贼✦`）、连放数枚都成立 | `班图南迁-草原风`、`机械#∞幽灵` |
| 对偶 | 符号把并列或对称的两半摆在一起，`&`、`#∞` 这类谁都不修饰谁。此前只用于两个受保护的稀有结构，**现推广为一般规则**：两段各自独立、分量相当就能这么用 | `金发笨蛋&战术人形`、`机械#∞幽灵` |
| 尾注 | 挂在句末收住「话没说完」的语气，判据见「尾饰」 | `玉树后庭花落♢`、`海边的Kafka猫♧` |

**对偶推广后的边界**：符号只是把两半摆在一起，不承担因果或从属。换成一句带修饰的话就只剩单方
陈述的，才算用对——`金发笨蛋&战术人形` 改成 `会战术的金发笨蛋` 就丢了一半。
成对与否不决定结构：`✦偷月贼✦` 前后各一枚是结构，`班图南迁-草原风` 中段只放一枚也是结构，
判据是符号有没有把它该强调的那段顶起来，不是左右对不对齐。

**`-` 与 `_` 的配额更多，但仍守三种判例**：这两个是断句/署名符号，不是装饰，
在三种位置上都可以用、且优先于别的符号——尤其**非尾饰的中段强调与对偶**，一枚断句就够，
不必刻意换成 `△`、`♤` 这类少见字形（前三类里的中段符号就该优先改回 `-` 或 `_`）。
**重复不是问题**：同一个位置判例下反复出现，不算同质化。尾注位置同样可以用，但**尾饰的符号池
略有不同**——相对中段多出数字、拉丁与希腊字母等（见「尾饰」一节的第一段），`-` `_` 只是其中一员，
不是尾饰的默认。`_` 在运营账号里仍是署名与断句（见该列判据），这一条只是不再把它当装饰分隔符删；
引擎占位的 `{sur}` `{given}` 和署名分隔 `_{given}` 不受影响。

### 已用符号做结构的条目：别当装饰删

下面这些不是没清理干净，是**符号本身就是这条的意思**。清理时要先认出它们：

| 条目 | 结构 | 为什么删不得 |
|-|-|-|
| `熵增∞` | 装饰符号 + 数学符号的双关 | `∞` 既装饰又读作「无穷」，删掉只剩一个抽象名词 |
| `机械#∞幽灵` | 词 ＋ `#∞` ＋ 词的对称夹心 | 全表另一种孤例，中间符号是这条的字形，拆开就变普通短语 |
| `金发笨蛋&战术人形` | 两个身份并列 | `&` 谁都不修饰谁，换成句子就变成单方陈述 |
| `Qing心灵语` | 谐音 + 字面 | 「倾心」「心灵语」两层同时在场 |
| `✦偷月贼✦`、`❀季风与她的猫❀` | 成对装饰 | 成对出现才是结构，不是句末一个符号 |
| `零∅`、`∫知逝の春解`、`深渊观测者ξ` | 符号即字形 | 这类条目靠符号认出它，删了就换了一条 |

判据：**把符号拿走，剩下的还是不是同一张脸？** 是，那就是装饰，可以删；
剩下那半句认不出是谁，就留着。

## 符号池：按码位范围，不按清单

「哪几枚能用」不能靠记忆，也不该靠一份越列越长的清单：清单会漏、会过时，还会让人以为没列出来的
就不能用。判据落成一条机械规则，谁算都算得一样，四步按顺序走：

1. **先折半**：全角 ASCII 变体（U+FF01–FF5E）、`〜`（U+301C）、`〰`（U+3030）、连字符与减号
   （U+2010–U+2015、U+2212）、斜杠与星号变体（U+2044、U+2215–U+2217）一律折成半角再判。
   **同一形状只留一个码位**：`～` 与 `~` 是同一枚符号，占用计数合并，形态判定也一致。
2. **整组排除**：
   - **默认彩色的 emoji 全免**：Unicode 属性 `Emoji_Presentation`（不给变体选择符也涂成彩色）的一律不收，
     包括 U+1F300 以上的一切图形（`🍒 🌊 🌙 💕 💸 🔥`）与 `⚡ ✅ ⏳ ⛅` 这类。
   - **默认黑白的单色 emoji 保留**：带 `Emoji` 属性、但不带 `Emoji_Presentation` 的那批照收——
     `☀ ☁ ☂ ☃ ☄ ✈ ✂ ☎ ☑ ❤ ♀ ♠ ♥ ♦ ☺ ⚙ ⚠`。它们不写变体选择符就是黑白字形，
     放在昵称尾巴里和 `★ ♤ ♪` 没有区别。
   - **没有 `Emoji` 属性的排印符号**照收：`☆ ♡ ♢ ♧ ♫ ☽ ☾ ☼ ⚐`。
   - **变体与组合**：`︎` `️`（U+FE0E / U+FE0F）、U+200D、U+20E3、肤色修饰、区旗码，全不收。
     这条与上一条配套：`☄` 可用，`☄️` 不可用——加了 U+FE0F 就是要求彩色，正好是第 2 步要挡的东西；
     U+FE0E 是看不见的「请用文本形态」，本来不写就是文本形态，也不必加。`˘͈ᵕ˘͈` 这类叠字同样出局。
   - **路径与引擎字符**：`\ / : * ? " < > | ,` 与 `{ } [ ]`。
3. **认区**：只在下表这十一组码位里取。
4. **认类**：只收 Unicode 大类 `Sm`（数学符号）与 `So`（其他符号）。于是标点（`• † ※ ′`）、
   字母式符号（`℃ ™ №`）、数字（`① Ⅻ`）、括号形状（`❨ ⟦`）自动出局，不用一枚一枚列。

四步都过才算可用。**清单是规则的产物**：要改池子就改表，清单重跑一遍；别去手改下面那几行字。

| 区 | 码位 | 枚数 | 收什么 |
|-|-|-|-|
| ASCII 排印 | U+0021–U+007E | 9 | 只收 ~ & # % + - _ = ^ |
| Latin-1 | U+00A1–U+00BF | 6 | ¦ © ¬ ® ° ± |
| Latin-1 运算 | U+00D7–U+00F7 | 2 | × ÷ |
| 箭头 | U+2190–U+21FF | 112 | 方向、趋势、位移 |
| 数学运算符 | U+2200–U+22FF | 252 | ∞ ∅ √ ∴ ⊕ 一类 |
| 几何图形 | U+25A0–U+25FF | 94 | ■ ▲ △ ◆ ◇ ○ ●，结构符号主力 |
| 杂项符号 | U+2600–U+26FF | 225 | 剔掉彩色 emoji 后剩星形、棋牌、骰子、音符、天气 |
| 装饰符号 | U+2700–U+27BF | 123 | ✓ ✦ ❀ ❖ 一类，含单色图标 |
| 数学符号 A | U+27C0–U+27EF | 36 | ⟡ ⟢ ⟣ 一类（括号形状不收） |

`.`（19 条）、`!`、`@`、`'`、`•`、`†`、`꧁꧂` 按标点算，不在这张越界表里。

### 这条规则定下来的四处旧写法

1. **`～` 归符号**：折半之后 `呼～我好爱这冷门角色`、`书画装裱刷浆糊～` 两条从纯中文变混合。
   以前半角 `~` 算混合、全角 `～` 算中文，差别只在编码，不在写法。
2. **emoji 分两档，不看印象看属性**：`♠ ♣ ♥ ♦ ❤ ☀ ☂ ☃ ☄ ✈ ☎ ☑ ♀ ☺ ⚙ ⚠` 默认黑白，可用；
   `⚡ ✅ ⛅ ✨ 🍒` 默认彩色，不可用。同一副花色 `♠` 与 `♤`、`♥` 与 `♡` 两套码位都在池子里，
   取哪套都行，但别再拿 `♠️`（带 U+FE0F）——那已经是彩色。
3. **`＊ ／ ｜ ﹨ ▏` 仍出局**：折半后落在路径字符或块元素上（`▏` 是块元素的制表符），
   这几枚以前常被当成「安全款」尾饰。
4. **变体选择符要清掉**：`☄️`、`☁︎` 这类写法在编辑器里看不出差别，进文件名和跨平台时就露馅。
   一律写成 `☄`、`☁`。

## 修饰配额：按位置抽，不按感觉配

符号池管「能用什么」，这一节管「这一次用哪类」。分开之后，配比不必等写完再回头数：
**在动手那一刻按权重抽**，一批写下来自然落在目标附近。这是抽取控制，不是事后平衡——
事后平衡的代价是回头重写已经立住的句子，而且改的往往只是符号，内容一点没动。

### 两张表

| 位置 | 类 | 目标 | 说明 |
|-|-|-|-|
| 中间 | `_` | 50% | 连接两段，最不打扰阅读，像用户名 |
| 中间 | `-` | 25% | 连接两段，读作「标题—副题」，硬一些 |
| 中间 | 其他 ASCII | 15% | `~ & # % + = ^` 与 `.`，做分隔或插入 |
| 中间 | 其他符号 | 10% | 符号池里的 `✦ ° ☾ ∞` |
| 末尾 | `_` | 12% | 被切断，像话没打完 |
| 末尾 | `-` | 5% | 同样是被切断，但句末挂横杠容易被读成破折号 |
| 末尾 | 字母 | 25% | `k`、`Ω`、`v2` 这类后缀，像名字的一部分 |
| 末尾 | 数字 | 8% | `07`、`404`、`2019`，防重最省事的手段；再高就像编号 |
| 末尾 | 其他 ASCII | 5% | `. ~ ! *` 等，最容易读成打字错误，压到最低 |
| 末尾 | 其他符号 | 45% | 符号池，含当尾饰的中文标点 `… 。 ！` |

两个位置权重差得远，是因为它们在句子里干的事不同：

- **中间是连接**，`_` 与 `-` 合起来七成半。这两个不承载语气，只负责把两段分开；
  符号一旦插进中间，读起来像代码，所以「其他符号」只留一成。
- **末尾是收尾**，符号占四成半，是这一位的主调。末尾那一枚不切词，也不参与断句，
  只把语气悬住——整条里唯一「挂一枚符号还像笔迹」的位置就是这里，所以它不像中间那样碍读。
  字母两成半次之，`柏林墙倒塌那夜k`、`深渊观测者ξ`、`灵Wo` 读起来像名字被截短了，
  不像挂了个装饰；`_` 一成二；`-` 只留 5%。
- **数字末尾压到 8%**：句末的数字最容易从「防重」读成「编号」或「参数」，
  只留防重那一档；定在一成半时，整列读起来像一批带版本号的文件。
- **其他 ASCII 末尾压到 5%**：`.`、`...`、`~` 这三样现表里最多，也最容易被读成标点错误。

### 什么叫「一次修饰」

- **只数主动加的修饰**，不数词语自带的符号。`Ctrl+Z人生模拟器` 的 `+`、`绝对零度-273.15` 的 `-`、
  `泛黄速写本.zip` 的 `.`、`功德+1+1+1` 的 `+` 都是正文，不进配额。现在表里中间那 26 处 ASCII，
  几乎全是这一类——所以中间的「其他 ASCII」实际是空的，不是超标。
- **中间、末尾各算一次，互不抵消**：`Anise_试用期进度50%` 中间一次 `_`、末尾一次 `%`。
- **汉字、假名、字母、数字本身不是修饰**：`Aimee` 的末字母不算「字母后缀」，
  `初音ミク` 的 `ミク` 也不算。字母类只数**挂在中文实词后面的短后缀**。
- **中文标点当尾饰时计入「其他符号」**：`间歇性摆烂中…` 的 `…` 和 `抽到下下签✦` 的 `✦` 干的是同一件事。
  但它在形态上仍算中文，不把这条推进混合。

### 其他符号：一次抽 20 个，再挑一枚

符号池 895 枚，抽一枚多半不合语义，重抽三次还是那几个直觉货（`~`、`°`、`✦`）。
抽 20 枚，从里面挑「和这句语气对得上」的那一枚，比反复重抽快，也比将就一枚强。

```
python .temp/nick_repolish/tail_pick.py --slot end --kind 其他符号
```

输出的 20 枚按「本表用得少的优先」加权，邻近行用过的会被排掉；其余类（字母、数字、ASCII）
默认给 8 枚够挑。从 20 枚里挑，按三条删：

1. **语义冲突的先删**：写睡觉的句子不挂 `☀`，写加班的句子不挂 `⚰`，写甜的句子不挂 `⚔`。
   符号不承载语义，但读的人会联想，联想反了就出戏。
2. **本列已用过同款的删**：同一列出现两次 `✦`，它就从语气变成模板（见「符号的位置判例」）。
3. **剩下按结构看**：成对符号（`✦偷月贼✦`）与句末单枚不是一回事，别把成对的拆一个来用。

不带 `--kind` 时按上表权重先抽类，再在该类里抽：

```
python .temp/nick_repolish/tail_pick.py --slot end      # 按末尾配额抽一类
python .temp/nick_repolish/tail_pick.py --slot mid      # 按中间配额抽一类
```

| 末尾 | `-` | 5% | 0% | 缺 4 |
| 末尾 | 字母 | 25% | 7.8%（6 条） | 缺 13 |
| 末尾 | 数字 | 8% | 7.8%（6 条） | 平 |
| 末尾 | 其他 ASCII | 5% | 19.5%（15 条） | 多 11 |
| 末尾 | 其他符号 | 45% | 51.9%（40 条） | 多 5 |

末尾分母是 77 条有效尾饰，另 6 条括号收尾、1 条叠字（`道理我都懂 ˘͈ᵕ˘͈`）本来就不合规，另案改。

这也正是「符号从左到右越用越少」的解法——不是给后几列多挂符号，而是让每条都有结构：
有主人的挂后缀（字母、数字），没主人的挂截断（`_`、`-`），剩下那近一半由末尾一枚符号收尾。
45% 说的是「有多少条该挂符号」，不是「一条挂几枚」——仍然是**一次一枚**。

配额是抽取权重，不是审计指标：一批改完偏离三五个点属正常，不回头重写。

## 造词与符号：靠字形和小语种取胜

原「外文单词（含自造）」「外文词组」两列合并为本类，**只收两种东西**：

1. **小语种**：外语字面对中文读者构成阅读困难，而不是通用做法。日语、韩语、法语进来
   （`neko`、`Ikari`、`Flora의Tale`、`Lumière étoilée`）；**歌词改写、生物拉丁学名不算**——
   它们有出处，按判定链回角色系列或具象类（判定链见 `nick_categories.md`）。
2. **非语言所用文字 / 非自然语言表达**：纯符号、变体字形、极简自造字形
   （`O.`、`UU`、`sᴀɪʟ`、`∫知逝の春解`）。**迷惑文本只当装饰、不影响主体理解的不算**，
   如 `𓆩虚妄𓆪` 读出来仍是「虚妄」，留在原列。

**通用外文不进本类**：`Opal`、`Night`、`Cherry`、`Joyful Voyager` 这类拿词典里就有的
外文词当昵称，靠的是字面而非阅读困难，按形态分流到各列的纯外文名额（见「三形态配比」）。

**只是英文词组合的也不进本类**：`CloudyJoker`、`LunaStar7`、`Cecilia_Sunlight`、`Nightwhisper`、
`Foxtrail✦` 这类，把两个现成英文词或专名用连写、下划线、空格、点号或数字后缀拼起来，
读懂不靠阅读困难、也不靠字形变形——**拆开是词典里查得到的词，就归通用外文**，同上分流。
尾部加一枚符号（如 `Foxtrail✦`）不改变主体是通用词组合的判断。
真正留下来的，是**词本身被改过**的那批：变体拼写（`Qlassy`、`Flyte`）、
非常用字形的压缩（`Bly`、`UU`、`O.`）、小语种（`neko`、`Ikari`）。

字形本身是内容：空格、下划线、大小写、是否缩写不是格式毛病，**都不要统一**：

| 形式 | 例 |
|-|-|
| 变体拼写 | `Qlassy`、`Flyte`、`Kiwii` |
| 极简字形 | `Bly`、`UU`、`O.`、`PandaG` |
| 小语种 | `neko`、`Ikari`、`Blanc`、`Lumière étoilée` |
| 非语言符号 | `sᴀɪʟ`、`Ezo_r`、`Nyxcryst` |

改一条的理由只能是**语义说得通、字形也匀称**，不能是「这一列空格太多」。
中英混搭（`Lost晨曦`、`Glimmer黯`、`Eureka豆浆`）另外按下一节的判据过。

## 中英混搭：先看视觉，再看语义

中英混搭读起来是一条还是两条，取决于**两段字的视觉分量是否相当**，其次才是意思接不接得上。
判据按这个顺序：

1. **视觉是否匀称**：两边字宽接近就是一条（`Lost晨曦` 五五开、`Eureka豆浆` 六四开），
   一边压倒另一边就是两条（`Glimmer黯`——`Glimmer` 七个字母压在单个汉字「黯」上，
   字宽三倍于它，读起来像拼错了）。
2. **语义是否连贯**：连得上就不动。`Lost晨曦`（迷路的黎明天光）成立，`Tree梦想家`（树上做梦）也成立。
3. 两条都过，**就不改**；只要有一条不过，才动：
   - 视觉不匀 → 把短的那边换成同义的两字词（`Glimmer黯` → `Glimmer Dusk`），或者整条换成中文。
   - 语义不通 → 走第 8 级换一条，不做局部修补。

**不要因为「这列英文太多了」去改**：造词与符号、自造意象短语两列本来就该以拉丁字母为主，
混搭里的英文比例不是病。

## 三形态配比

统计和配发都按这一套口径，不按直觉判断。后三类拆成四形态，数字单列：

- **纯中文**：只有汉字、中文标点（含 `，`、`、`、`？`、`！`、`（）`、`“”` 等强语义标点）、
  **中文数字**（`第七页`、`第三圈`）和 `{sur}` / `{given}` 占位符。中文标点与中文数字都算中文，不算符号。
- **中文 + 非尾注数字**：含汉字，句中的**阿拉伯数字**是编号、血量、等级、次数、图鉴号等
  **屏幕显示的值**（`御坂1234号`、`宝可梦151号收服球`、`追光灯下3排尘埃`）。只有中文和非尾注数字才算这一类；
  一旦还有外文或非中文符号，就归混合。
- **混合**：含汉字，同时含外文、任何非中文符号（彩色 emoji 也算，虽然它已整组不收）或**句末阿拉伯数字**。
  中文强语义标点本身不构成混杂；尾注数字是防重语气，归这一类。
- **纯外文**：不含汉字；纯符号、纯阿拉伯数字也归这里。`造词与符号` 一列整列属纯外文形态。

**数字只认阿拉伯数字 `0~9`。** 中文数字是汉字，形态上算纯中文；滥用靠上层判据解决——
**展示近段状态、不展示瞬时观察及其反思**（见 `nick_categories.md`「硬约束」），不要写成
「停在第 7 天」「还剩一半」；中文数字同样按这条改写成状态，但**不靠「不用数字」、也不为凑配额
换成阿拉伯数字**。

目标（比例是生产配额，不是条数上限，不要为了凑数硬塞）：

| 分组 | 含列 | 纯中文 : 中文+数字 : 混合 : 纯外文 |
|-|-|-|
| 前三类 | 历史典故/演义、影剧、文学 | 80 : 5 : 15 : 0 |
| 后三类 | 游戏、其他虚拟角色情节舞台、文娱 | 70 : 5 : 20 : 5 |
| 城市空间·物件本体 | 城市空间、物件本体 | 70 : — : 25 : 5（暂不单列数字） |
| 现实日常～天文地理（余下五列） | 现实日常、野生动物/古生物、音乐/美术、抽象概念、天文地理/人类学与玄学 | 70 : — : 25 : 5（暂不单列数字） |
| 意象系列＋情感 | 意象·夜空、意象·气象、意象·其他自然、意象·情绪、意象·人格化动物与智能、意象·器物、情感 | 60 : — : 35 : 5（不写数字） |
| 人名系列 | 人名（非直接引用）/短昵称、运营账号、事业 | —（不配平） |

**「—」的三组不单列数字**：句中阿拉伯数字按纯中文计，句末数字归混合（它是防重语气，
不是屏幕显示的值）。只有后三类把「中文+数字」单列，且只算屏幕显示值那一种。
条数不能被 20 整分的列，按最接近的整数折算（28 条的 `70:—:25:5` 就是 20 / 7 / 1）。

**人名系列不配平**：人名、运营账号、事业三列的评价标准是「有没有主人、主人叫不叫得出口」，
形态只是署名的副产品——中文固定名、改写音译、日式名、外文名、占位符各占多少，本身就是这三列的
内容。按 `70 : — : 25 : 5` 去配，等于反过来要求改署名：要么给中文名贴一个 `·Ji` 凑混合，
要么把外文署名削成中文凑纯中文。事业虽按岗位现场判归属，落名比例本就过半，一同归入。

**抽象概念是反向的一列**：它该以中文概念为主，不硬凑外文字母，也不把概念写成具体物。

**为什么前三类与后三类分开算**：

- **后三类**（游戏、二次元、文娱）粉丝集中，昵称常有「假扮成本人 / 亲友 / 当地居民」的动机，
  直接叫出角色原名、用外文身份都说得通，纯外文有发挥空间，留 5%。
- **前三类**（历史、影剧、文学）的取法基本只有头衔式——`场务`、`目击者`、`第一读者`，
  不会有人假扮成拿破仑本人或 Bertolt 的亲友；而且很少人记得这些角色的外文原名。
  纯外文在这里没有发挥空间，**归 0**；显示型数字同样单列占 5%，即 80 : 5 : 15 : 0。
  要混搭只能用熟知的专名片段（`记录赤壁Wind的周公瑾`、`爱丽丝Fall指南`），不写整段外文原名。

**纯外文的 5% 是上限式的目标，不必填满**：改写过的外文词（变体拼写、小语种、极简字形）按
「造词与符号」的判据留在那一列，能分流到正文列的通用外文数量有限；缺额宁可留空，
也不要靠给中文条目贴外文字母来补。取词只用两种：通用外文词，以及待分流池里语义对得上的条目
（`Jump Twice`、`Intern`、`Overtime` 就是这一类）。

**怎么补混合**：能在词与词之间断开的，用 `-` 做中段强调，把后半截顶起来（`白桃-乌龙`、
`丹顶鹤-掠过沼泽`、`本命盘-第八宫`），位置对了不算模板；语气没落地的短句用尾饰（`戒辣又破戒~`、
`算命的改口~`、`上上签写着~`）。`…` 属中文强语义标点，不算混合，别拿它充数。

**符号不参与形态配比，任何形态都能夹**：混杂式和纯外文里都可以挂 `△`、`♤`、`☼`、`✦`
（可选范围见「符号池」，加多少见「修饰配额」），形态仍按「有没有汉字、有没有外文/非中文符号」判；
一片条目全带同一种符号才是问题。

**混杂式内部再分三种，按 2 : 3 : 1 配**（约 1/3、1/2、1/6）。这条只对前六类硬配；
城市空间·物件本体与余下五列不按它凑：

| subtype | 例 |
|-|-|
| 中文 + 非中文标点符号 | `班图南迁-草原风`、`玉树后庭花落♢`、`翻牌的那个荷官♤` |
| 中文 + 外文 | `记录赤壁Wind的周公瑾`、`亚历山大东征路上的Moon` |
| 中文 + 外文 + 符号 | `尼罗河畔_Papyrus`、`布鲁斯Wayne跟班☽` |

**中文 + 符号也是混杂式，不必加外文**。判定只问「有没有外文或非中文符号」——
只有非中文符号照样算混杂，这是三种里最重要的一类，别把它当成纯中文。

**外文别总放在句首**：把外文统一挪到句首做「外文替换开头」，做多了就成了格式。
外文可以落在句中（`记录赤壁Wind的周公瑾`、`爱丽丝Fall指南`）或句末
（`亚历山大东征路上的Moon`），位置跟着原句的词序走，不统一挪到前面。
前三类虽然纯外文归 0，混搭里用熟知的专名片段仍可以带符号。

人名系列（人名、运营账号、事业）与网络meme、自造意象短语、短小网感、造词与符号不在这几组里，
形态顺其自然，不按上表配平。

## 表头数字

`类/数字` 里的数字是**生产配额**，不是条数上限；实际条数超出不算错。按判定顺序判归属，
不要为了凑配额把条目塞进相邻类。
